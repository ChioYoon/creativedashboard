# 장르별 AI 프롬프트 (Stage 3) 설계 스펙

작성 2026-06-23 · 브레인스토밍 합의 기반.

---

## 0. 한 줄 요약

타이틀별 **게임 컨텍스트 MD**와 **장르별 System Instruction**을 분리해 Gemini 태깅이 각 게임의 특성을 반영하도록 한다. 기존 캐시·버전 핀·파이프라인 흐름은 최소 변경.

---

## 1. 배경 · 문제

- 현행 `SYSTEM_INSTRUCTION`은 펩 히어로즈(캐릭터 컬렉션 RPG) 전용으로 튜닝됨.
  - 캐릭터 연출 4분할(SD·라인업·주인공·액션)이 펩 소재 기준.
  - factual 게임 정보(캐릭터 이름·USP·타깃)가 없어 `one_line_insight`·`kpi_reality_check`가 범용적.
- 도원암귀(무협 액션 RPG) 소재가 추가될 때 현행 instruction을 그대로 쓰면 잘못된 강점 분류 발생 가능.
- Stage 3 목표: **타이틀별 맞춤 분석 지침 + 게임 factual 컨텍스트** 제공.

---

## 2. 설계 원칙

1. **두 레이어 분리**: 분석 지침(장르 Instruction) ↔ 게임 factual 정보(게임 컨텍스트 MD).
2. **캐시 격리**: 장르별 version suffix → 타이틀 A 변경이 타이틀 B 재태깅을 트리거하지 않음.
3. **Graceful 폴백**: genre 미지정 → 기본값(`character_collection_rpg`), MD 파일 없음 → 경고 후 스킵.
4. **점진적 개선**: MD는 소재 관찰에 따라 계속 개선되는 살아있는 문서. Instruction은 소재 실물 확인 후 정교화.

## 3. 아키텍처

```
titles.json
  ├── _pipeline_genre: "martial_arts_action_rpg"
  └── _pipeline_game_context_file: "pipeline/game_context/tougenanki.md"

tagger.py
  ├── GENRE_INSTRUCTIONS: dict[genre_id → (instruction_text, version_suffix)]
  │     ├── "character_collection_rpg"  → (SYSTEM_INSTRUCTION_CHARACTER_RPG, "char-rpg")
  │     └── "martial_arts_action_rpg"   → (SYSTEM_INSTRUCTION_MARTIAL_ARTS_RPG, "martial-v1")
  ├── DEFAULT_GENRE = "character_collection_rpg"
  ├── get_system_instruction(genre: str) → str
  └── prompt_version(genre: str = DEFAULT_GENRE) → str
        # 펩:    "v3.3-...-char-rpg"
        # 도원암귀: "v3.3-...-martial-v1"

main.py
  ├── 시작 시 _pipeline_game_context_file 로드 (없으면 game_ctx = "", WARNING)
  ├── extra_context = game_ctx_block + kpi_context_block
  └── tag_creative(file_path, extra_context, genre=genre) 호출

pipeline/game_context/
  ├── pepp-us.md      ← 펩 히어로즈 factual 컨텍스트
  └── tougenanki.md   ← 도원암귀 factual 컨텍스트
```

## 4. 컴포넌트 상세

### 4-A. titles.json 신규 필드

| 필드 | 타입 | 기본값 | 설명 |
|------|------|--------|------|
| `_pipeline_genre` | string | `"character_collection_rpg"` | 장르 Instruction 선택 키 |
| `_pipeline_game_context_file` | string | null | 게임 컨텍스트 MD 상대경로 |

**적용 예시:**
```json
// pepp-us
{
  "_pipeline_genre": "character_collection_rpg",
  "_pipeline_game_context_file": "pipeline/game_context/pepp-us.md"
}

// tougenanki
{
  "_pipeline_genre": "martial_arts_action_rpg",
  "_pipeline_game_context_file": "pipeline/game_context/tougenanki.md"
}
```

### 4-B. tagger.py 변경

```python
BASE_PROMPT_VERSION = "v3.3-2026.06.13-character-split-single"

# 기존 SYSTEM_INSTRUCTION → 이름만 변경, 내용 무변경
SYSTEM_INSTRUCTION_CHARACTER_RPG = """...(현행 내용)..."""

# 신규 — 도원암귀용 (소재 확보 전 template)
SYSTEM_INSTRUCTION_MARTIAL_ARTS_RPG = """...(공통 골격 + 캐릭터 가이드 placeholder)..."""

GENRE_INSTRUCTIONS: dict[str, tuple[str, str]] = {
    "character_collection_rpg": (SYSTEM_INSTRUCTION_CHARACTER_RPG, "char-rpg"),
    "martial_arts_action_rpg":  (SYSTEM_INSTRUCTION_MARTIAL_ARTS_RPG, "martial-v1"),
}
DEFAULT_GENRE = "character_collection_rpg"

def get_system_instruction(genre: str) -> str:
    return GENRE_INSTRUCTIONS.get(genre, GENRE_INSTRUCTIONS[DEFAULT_GENRE])[0]

def prompt_version(genre: str = DEFAULT_GENRE) -> str:
    suffix = GENRE_INSTRUCTIONS.get(genre, GENRE_INSTRUCTIONS[DEFAULT_GENRE])[1]
    return f"{BASE_PROMPT_VERSION}-{suffix}"
```

`GeminiTagger.tag_creative()` 시그니처:
```python
def tag_creative(self, file_path: Path, extra_context: str = "", genre: str = DEFAULT_GENRE) -> CreativeTag:
    instruction = get_system_instruction(genre)
    contents = [asset, instruction]
    if extra_context:
        contents.append(extra_context)
    ...
```

### 4-C. cache.py — 변경 불필요

캐시 키 구조: `sha256(파일 바이트) :: prompt_version`. `prompt_version(genre)`이 장르별로 다른 문자열을 반환하므로 `cache.py` 수정 없이 자동으로 캐시 격리됩니다.

### 4-E. 버전 핀 호환성

`_pipeline_prompt_version_pin`이 있으면 `prompt_version(genre)` 전체를 덮어씁니다 (기존 동작 유지).

### 4-D. 게임 컨텍스트 MD 형식

```markdown
# 게임 컨텍스트 — [타이틀명]
<!-- Gemini 태깅 시 extra_context로 주입되는 게임 배경 정보. -->

## 기본 정보
- 장르:
- 세계관/배경:
- 주요 캐릭터: (이름, 역할, 특징)
- 핵심 게임플레이:

## UA 소재 전략 포인트
- 우선 강조할 USP:
- 경쟁 게임 대비 차별점:
- 주요 타겟 유저:
- 잘 먹히는 후킹 유형 (예상 또는 관찰):

## 피할 표현·금기 사항
- (있을 경우만)
```

### 4-E. NotebookLM/Gemini 활용 워크플로우

```
[소스 자료] 게임 기획서, 스토어 페이지, 캐릭터 설정집, UA 전략 메모
     ↓ NotebookLM 업로드 → 핵심 요약 생성
     ↓ Gemini에 아래 프롬프트 입력:

"아래 요약을 참고해 pipeline/game_context/{title}.md 형식으로 정리해줘.
 섹션: 기본 정보 / UA 소재 전략 포인트 / 피할 표현
 요약: [NotebookLM 출력 붙여넣기]"

     ↓ 결과를 pipeline/game_context/{title}.md 에 저장
     → 파이프라인이 자동 로드
```

**개선 사이클:**
1. **초안**: 소재 없이 게임 기획 자료 기반으로 MD 작성
2. **보완**: 실제 소재를 보며 "전략 포인트" 섹션 업데이트
3. **정교화**: 태깅 결과에서 어긋난 분류 발견 시 Instruction 수정 + version bump

## 5. 도원암귀 Instruction 템플릿 구조

공통 유지(펩과 동일):
- 10개 필드 정의
- 분석 원칙 (근거 강제, 처방형 어미 등)
- Few-shot 예시 A/B/C (장르 무관, 보편 소재 예시)

**교체 섹션 — 캐릭터 강점 가이드:**
```
[현행 펩]
캐릭터 연출은 다음 4개 중 가장 지배적인 1개만 선택:
  · SD/귀여운 캐릭터 연출
  · 다수 캐릭터 라인업
  · 단일 주인공 스포트라이트
  · 캐릭터 액션/전투 연출

[도원암귀 v1 placeholder — 소재 확보 후 실물 기반으로 교체]
캐릭터/전투 연출은 다음 중 가장 지배적인 1개만 선택:
  · '단일 주인공 무공 연출' — 주인공 1명의 스킬/무공 액션이 화면 지배
  · '세계관·배경 몰입 연출' — 동양 무협 배경·분위기·미장센이 핵심
  · '군중 전투 장면' — 다수 적 상대 광역 스킬·전장 장면
  · '드라마틱 감정·서사 연출' — 표정·갈등·내러티브 클로즈업
  ※ 소재 실물 관찰 후 레이블 및 기준 정교화 예정 (v1 → v2 bump)
```

## 6. 테스트 전략

| 단계 | 검증 내용 | 방법 |
|------|-----------|------|
| T1 | 펩 기존 캐시 무변경 | `prompt_version("character_collection_rpg")` 출력 확인, 파이프라인 dry-run |
| T2 | 장르별 version suffix 분리 | `prompt_version("character_collection_rpg")` ≠ `prompt_version("martial_arts_action_rpg")` 단위 확인 |
| T3 | game_context MD 주입 효과 | 펩 `--pilot --limit 5`: MD 없는 버전 vs MD 있는 버전 `one_line_insight` 비교 |
| T4 | MD 파일 없음 graceful skip | `_pipeline_game_context_file` 경로 오류 시 WARNING 출력 후 태깅 계속 진행 |
| T5 | 도원암귀 신규 태깅 | `--pilot --limit 3`으로 장르 instruction + MD 적용 결과 확인 |
