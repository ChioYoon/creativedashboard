# 누적 마케터 컨텍스트 (1b) — 설계 문서

**작성일:** 2026-07-09
**범위:** 파이프라인(Python: schemas·main·해시) + 프런트(data-source·step1 보고서·pre_eval). 편집 UI 없음.
**한 줄:** 공유·커밋되는 게임/마케터 컨텍스트(`game_context/{title}.md`)를 출력 JSON에 임베드해 보고서·사전평가가 팀 전체에 걸쳐 읽게 하고, 컨텍스트가 바뀌면 재태깅을 권장하는 스테일 알림을 붙인다.

---

## 1. 목표

마케터 인사이트가 (a) **미래 보고서에 팀 전체로 반영**되고(1a의 개인 localStorage 한계 해소), (b) **컨텍스트 변경 시 재분석(재태깅) 여부를 사람이 검토·실행**할 수 있게 한다. 태깅·사전평가로의 컨텍스트 반영은 이미 `build_extra_context`·`_peGameContext`로 존재하므로, 1b는 **보고서 연결**과 **재태깅 스테일 알림**을 추가한다.

**전제(정적 사이트):** 브라우저는 공유 저장소에 못 쓴다. 공유·영속은 **커밋되는 `pipeline/game_context/{title}.md`**가 단일 소스이며, 파이프라인이 이를 출력 JSON에 임베드해 프런트가 안정적으로 읽는다. 편집은 기존대로 `.md` 직접 수정(대시보드 편집 UI 없음). 재태깅은 사람이 `--no-cache`로 실행(자동 아님).

## 2. 비목표 (YAGNI)

- 대시보드 내 컨텍스트 편집·내보내기 UI → 범위 밖(마케터가 `.md` 직접 관리).
- 컨텍스트 변경 자동 재태깅(캐시 키에 해시 포함) → 채택 안 함(사소한 수정도 전량 재태깅·비용↑). 대신 명시적 `--no-cache` + 스테일 알림.
- 컨텍스트 구조화(섹션 파싱을 파이프라인에서) → 전문 임베드, 프런트가 필요한 섹션 슬라이스.

## 3. 아키텍처 배경 (탐색 결과 · 정확한 앵커)

- 게임 컨텍스트 로드: `pipeline/main.py:75 _load_game_context()`(경로는 title override `_pipeline_game_context_file`에서), `:659 game_ctx = _load_game_context(...)`. `build_extra_context()`(`:873`)가 `[게임 컨텍스트]\n{game_ctx}` + pool + 소재 성과를 합쳐 `tag_creative(extra_context=...)`(`:938`)로 전달.
- 출력 JSON 조립: `pipeline/main.py:1142 CreativeDataset(...)` 인스턴스화 → `:1167 model_dump(by_alias=True)` → `public/data/{title}.json`. 스키마 `pipeline/schemas.py:565 CreativeDataset`(schema_version·title_id·creatives·metrics·campaign_canonical·unmatched_assets).
- 태그 캐시 키: `pipeline/cache.py:65 make_key(sha, prompt_version) = f"{sha}::{prompt_version}"` — **컨텍스트 미포함**. 읽기 `main.py:918 cached = None if cfg["no_cache"] else cache.get(sha, pversion)`. `--no-cache`(`:371,554`)는 읽기 우회(강제 재태깅) 후 쓰기(`:940`).
- 프런트 정규화: `js/data-source.js:135 normalizeFromJson` → `_meta`가 **명시적 화이트리스트**(title_id·generated_at·campaign_canonical·unmatched_assets 등). 신규 top-level 필드는 드롭됨 → `_meta`에 추가해야 도달.
- 보고서 프롬프트: `step1_integrated.html:5528 buildReportNarrativePrompt(data, tags, note)` — `note`(개인 localStorage)만 사용(`:5471` 주석 "공유·영속은 후속 1b"). `generateSummaryReport`(`:5480` note 읽기·`:5490` buildReportNarrative 호출).
- 사전평가: `pre_eval.html:195 _peGameContext(titleId)` → `fetch('pipeline/game_context/{titleId}.md')`(정적 서빙 취약 — `.nojekyll` 없음).
- `zeus.md` 섹션: §1 기본정보 / §2 게임플레이 / §3 캐릭터 / **§4 UA 전략·소재 관점** / **§5 금기(Do Not)**. 헤딩은 `## **4\. ...**` 형식(볼드·이스케이프 번호).

## 4. 상세 설계

### 4.1 Thread 1 — 보고서가 공유 컨텍스트 반영

**(파이프라인) 컨텍스트 임베드**
- `pipeline/schemas.py:565` `CreativeDataset`에 필드 추가: `game_context: str = ""`.
- `pipeline/main.py:1142` `CreativeDataset(...)` 생성자에 `game_context=game_ctx` 추가(`game_ctx`는 `:659`에서 로드됨, 전문). → 출력 JSON top-level에 `game_context` 문자열 포함.

**(프런트) 노출·소비**
- `js/data-source.js` `_meta`에 `game_context: data.game_context || ''` 추가.
- **보고서**(`step1_integrated.html`):
  - 로드된 데이터의 `_meta.game_context`에 접근할 수 있는 지점에서 값을 확보(현재 `_meta.campaign_canonical` 등을 쓰는 것과 동일 경로).
  - `buildReportNarrativePrompt(data, tags, note, sharedContext)`로 인자 추가. `sharedContext`는 **§4·§5만 추출·상한(~1500자)**한 텍스트.
  - 프롬프트에 배경 블록 주입(있을 때만): `L.push('[게임/UA 컨텍스트 — 팀 공유]'); L.push(sharedContext);` — 데이터 근거로 분석하되 이 컨텍스트를 프레이밍으로 활용하라는 규칙 1줄. 기존 `[마케터 의견]`(note) 블록은 유지.
  - 섹션 추출 유틸: `## **4` 이후~EOF 슬라이스(정규식 `/^##\s*\*\*\s*4/m`부터), 없으면 앞부분 1500자 폴백. 컨텍스트 없으면 블록 생략(무회귀).
  - 플러밍: `buildReportNarrative`·`generateSummaryReport`에 sharedContext 전달.
- **사전평가**(`pre_eval.html`): `_peGameContext`를 **로드된 JSON의 game_context 사용**으로 전환(이미 `runPreEval`에서 `loadCreativeData`로 데이터 로드 → `normalized._meta.game_context` 사용). 취약한 `.md` fetch 제거. 없으면 빈 문자열(무회귀).

**무회귀:** 구 JSON(game_context 필드 없음)이면 `_meta.game_context=''` → 보고서 컨텍스트 블록 생략·사전평가 컨텍스트 없이 진행. 기능은 다음 파이프라인 실행 후 완전 동작.

### 4.2 Thread 2 — 명시적 재태깅 + 스테일 알림

**(파이프라인) 해시 기록**
- 컨텍스트 해시 헬퍼(예: `pipeline/main.py` 또는 유틸): `_context_sha(game_ctx) = sha256(game_ctx.encode()).hexdigest()[:16]`(빈 문자열이면 '').
- `CreativeDataset.metrics`에 `game_context_sha` 기록(`main.py:1142` 근처, metrics dict에 추가). 태깅 시점의 컨텍스트를 식별.

**(파이프라인) 실행 시작 시 스테일 검사**
- 실행 초반(game_ctx 로드 후, 태깅 루프 전), 기존 출력 JSON(`public/data/{title}.json`)이 있으면 그 `metrics.game_context_sha`를 읽어 현재 `_context_sha(game_ctx)`와 비교.
- 다르고 `--no-cache`가 아니면: **경고 출력** — `⚠️ 게임 컨텍스트가 마지막 태깅 이후 변경됨(이전 <sha> → 현재 <sha>). 캐시된 태그는 이전 컨텍스트 기준입니다. 태그를 갱신하려면 --no-cache로 재실행하세요.` (실행은 계속 — 사람이 판단.)
- `--no-cache`면 정상 재태깅이므로 경고 불필요(또는 "재태깅 진행" 정보 로그).

**동작:** 일반 실행=캐시 유지(저비용) + 스테일 시 경고. 사람이 경고 보고 `--no-cache` 재실행 판단. 자동 무효화 없음.
