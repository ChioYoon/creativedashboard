# 타이틀 셀프 등록 (등록부 xlsx → titles.json 자동 생성) 설계 스펙

작성 2026-06-25 · 브레인스토밍 합의 기반.

---

## 0. 한 줄 요약

타이틀 담당자가 **공유 드라이브의 등록부 `.xlsx`** 에 자기 타이틀 정보를 직접 입력하면, nightly 파이프라인이 그 파일을 **로컬 마운트(G:\)에서 읽어 `js/titles.json` 을 자동 생성**한다. 운영자(님)는 토큰·기술 필드만 보완. 인증·API·공개 공유 불필요.

---

## 1. 배경 · 문제

- 현재 타이틀 등록 = 운영자가 `js/titles.json` 을 **손으로 편집**. 담당자가 늘면 병목.
- 목표: **담당자 셀프 등록**. 단, 토큰(Gemini·MMP·Google Ads)은 운영자가 계속 관리.
- **제약 (검증 완료)**:
  - 대시보드는 백엔드 없는 정적 사이트 → 화면 폼으로 titles.json 저장 불가.
  - 파이프라인·토큰·GDrive 마운트가 **운영자 PC 중앙집중** → 새 타이틀 소재 폴더가 그 PC에서 접근 가능한 공유 드라이브여야 함.
  - **컴투스 Workspace가 게시/공유 시트의 비로그인 접근을 차단**(실측: 게시 URL·export URL 모두 401) → 공개 CSV/Sheets 직접 fetch 불가.
- 결론: **공유 드라이브에 `.xlsx` 를 두고 파이프라인이 로컬 파일로 읽는 방식(인증 불필요)** 채택.

## 2. 확정 결정 (브레인스토밍 Q&A)

| 항목 | 결정 |
|------|------|
| 제출 방식 | Google 등록부(담당자 셀프 입력) |
| 읽기 방식 | **공유 드라이브 `.xlsx` 로컬 읽기**(openpyxl) — 인증/API/공개 공유 불필요 |
| titles.json | **등록부에서 자동 생성**(손편집 중단) |
| 고급 설정 | `js/titles_overrides.json`(운영자) deep-merge |
| 분업 | 담당자 7컬럼(자기 타이틀) / 운영자 5컬럼(토큰·기술) |
| MMP | `MMP 종류` + `MMP 앱 식별자` 로 일반화(Airbridge/AppsFlyer/없음) |

## 3. 아키텍처

```
공유 드라이브의 등록부.xlsx  (예: G:\공유 드라이브\[R마케팅] ...\CLOOP_타이틀_등록부.xlsx)
   │  담당자가 Google 드라이브에서 편집 (Drive가 .xlsx 를 시트 편집기로 열어줌)
   │  Drive for Desktop 이 로컬(G:\)로 동기화
   ↓ nightly 시작 시
pipeline/registry.py  ──  build_titles_json()
   1) 등록부 xlsx 읽기 (openpyxl) → 행 파싱
   2) 활성화=Y 행만, 필드 매핑 → 타이틀 dict 생성 (+ 파생/기본값)
   3) js/titles_overrides.json deep-merge (고급 오버라이드)
   4) 검증 통과 시 js/titles.json 교체 (실패 시 기존 보존)
   ↓
main.py  ──  기존 흐름 (생성된 titles.json 으로 다중 타이틀 배치)
   ↓ nightly auto-commit/push
대시보드(GitHub Pages)가 js/titles.json 읽음
```

**Opt-in**: 등록부 경로(`CLOOP_REGISTRY_XLSX` env)가 설정됐을 때만 생성 단계 동작. 미설정 시 기존 titles.json 그대로(하위 호환).

## 4. 컴포넌트 상세

### 4-A. 등록부 xlsx 스키마 (첫 시트, 1행=헤더)

| # | 컬럼(헤더) | 입력 | 필수 | titles.json 매핑 |
|---|-----------|------|------|------------------|
| 1 | 타이틀 ID | 담당자 | ✅ | `id` |
| 2 | 타이틀명 | 담당자 | ✅ | `name` |
| 3 | 소재 폴더 링크 | 담당자 |  | `drive_folder_url` |
| 4 | 소재 유형 | 담당자 |  | `_pipeline_types` (예 `BNR,VID` → `["BNR","VID"]`) |
| 5 | 장르 | 담당자 |  | `_pipeline_genre` (미입력 시 기본 `character_collection_rpg`) |
| 6 | 광고 성과 연동 | 담당자 |  | `_pipeline_kpi_enabled` (`Y`→true) |
| 7 | 비고/요청 | 담당자 |  | (반영 안 함, 참고용) |
| 8 | 로컬 스캔 경로 | 운영자 | ✅(활성화 시) | `_pipeline_creatives_root` |
| 9 | Google Ads ID | 운영자 |  | `_pipeline_google_ads_customer_id` |
| 10 | MMP 종류 | 운영자 |  | `Airbridge`/`AppsFlyer`/`없음` → 4-B 참조 |
| 11 | MMP 앱 식별자 | 운영자 |  | MMP 앱 식별자(Airbridge app_name 등) |
| 12 | 활성화 | 운영자 | — | `Y` 인 행만 생성 대상 (`_pipeline_enabled: true`) |

- 편집: 담당자는 Drive에서 `.xlsx` 를 열어(시트 편집기) 1~7 입력. 운영자가 8~12 확정.
- 컬럼은 **헤더명으로 매칭**(순서 무관, 추가 컬럼 무시).

### 4-B. 필드 매핑 규칙

행 → 타이틀 dict 생성:
```python
title = {
  "id": row["타이틀 ID"].strip(),
  "name": row["타이틀명"].strip(),
  "json_url": f"public/data/{id}.json",                       # 파생
  "drive_folder_url": row.get("소재 폴더 링크", "").strip(),   # 없으면 키 생략
  "_pipeline_enabled": (row["활성화"].upper() == "Y"),
  "_pipeline_creatives_root": row.get("로컬 스캔 경로", "").strip(),
  "_pipeline_scan_mode": "by-filename",                        # 기본
  "_pipeline_types": [t.strip() for t in row.get("소재 유형","BNR,VID").split(",") if t.strip()],
  "_pipeline_genre": row.get("장르","").strip() or "character_collection_rpg",
  "_pipeline_kpi_enabled": (row.get("광고 성과 연동","N").upper() == "Y"),
}
# game_context: 규칙 경로에 파일 있으면 자동 연결
if Path(f"pipeline/game_context/{id}.md").exists():
    title["_pipeline_game_context_file"] = f"pipeline/game_context/{id}.md"
# KPI=Y 일 때 Google Ads
if title["_pipeline_kpi_enabled"]:
    cid = row.get("Google Ads ID","").strip()
    if cid:
        title["_pipeline_google_ads_customer_id"] = cid
        title["_pipeline_google_ads_campaign_filter"] = []          # 기본
    # MMP
    mmp = row.get("MMP 종류","").strip().lower()
    if mmp == "airbridge":
        title["_pipeline_airbridge_enabled"] = True
        title["_pipeline_airbridge_exclude_channels"] = ["google.adwords","unattributed","appstore","sns","airbridge_sdk_test"]  # 기본
        title["_pipeline_airbridge_usd_to_krw"] = 1500              # 기본
        # ⚠️ 타이틀별 Airbridge app(MMP 앱 식별자) 소비는 멀티타이틀 MMP 보강 시 (현재 .env 단일 앱)
    elif mmp == "appsflyer":
        pass   # AppsFlyer 소스 미구현(로드맵) — 종류만 보존, 구현 시 라우팅
```

- **파생값**: `json_url`, `game_context_file`(규칙 경로 존재 시).
- **기본값**: scan_mode=`by-filename`, types=`["BNR","VID"]`, genre=`character_collection_rpg`, airbridge exclude/fx, campaign_filter=`[]`.
- 빈 값 컬럼은 해당 키 생략(파이프라인 기본 동작 유지).

### 4-C. 오버라이드 파일 (`js/titles_overrides.json`)

운영자 관리. 등록부로 표현 안 되는 **드문 고급 설정**을 타이틀별로 deep-merge.
```json
{
  "tougenanki": { "_pipeline_prompt_version_pin": "v3.3-2026.06.13-character-split-single" },
  "pepp-us":    { "_pipeline_google_ads_window_days": 159 }
}
```
- 생성 결과(등록부 기반) 위에 **타이틀 id 기준 얕은 병합**(키 단위 override).
- 없으면 무시(빈 파일/파일 없음 허용).

### 4-D. 생성 함수 (`pipeline/registry.py`)

```
build_titles_json(registry_xlsx_path, out_path="js/titles.json",
                  overrides_path="js/titles_overrides.json") -> dict(summary)
  1. xlsx 없으면 → (skip, 기존 titles.json 보존) 반환
  2. openpyxl 로 첫 시트 읽기 → 헤더 매핑 → 행 dict 리스트
  3. 각 행: 활성화=Y 아니면 skip. id·name 없으면 skip+warn.
            활성화=Y인데 creatives_root 없으면 skip+warn.
  4. 매핑(4-B) → 타이틀 dict
  5. overrides deep-merge(4-C)
  6. 기존 titles.json 의 sample 더미 항목 보존(있으면 append)
  7. 결과를 임시 검증(JSON 직렬화·최소 1개 타이틀) 후 out_path 교체
     실패 시 기존 보존 + 에러 로그
```
- main.py 시작부에서 `CLOOP_REGISTRY_XLSX` env 있으면 호출.
- 콘솔/이메일에 요약(생성 N개·스킵 M개·사유).

### 4-E. 안전장치

- **활성화=Y 행만** 반영(작성 중 행 제외).
- **필수 누락 스킵 + 경고**(id/name/creatives_root). 한 행 오류가 전체를 깨지 않음.
- **원자적 교체**: 임시 생성·검증 후 교체. 읽기/파싱 실패 시 **기존 titles.json 그대로 보존**.
- `sample` 더미 항목 보존(대시보드 Stage1 검증용).
- env 미설정 시 생성 단계 자체를 건너뜀(기존 수동 titles.json 유지).
