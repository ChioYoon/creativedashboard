# 군집 차수 트렌드 심화 — 설계

**작성일:** 2026-07-02
**대상:** `step2_clustering.html`
**상위 맥락:** 2026-06-21 스펙(`2026-06-21-군집화-2라운드-A-자동인사이트-design.md`)에서 "이전 차수 대비 트렌드"가 Non-Goal(차기)로 명시 보류됐던 항목. 이번 세션에서 "차수"의 의미를 재확인한 결과, **시간에 따른 군집 스냅샷 비교**(주간/월간)로 확정.

## 배경 조사

- 코드베이스의 "차수"는 파이프라인 스캔 시점의 릴리즈 단계(사전예약/상시/선론칭) 필터를 가리키며(`pipeline/scanner.py`), **소재별로 최종 JSON에 저장되지 않음**(스캔 필터일 뿐, 영구 필드 아님). 이 의미로는 현재 데이터로 트렌드를 만들 수 없음.
- 사용자 확정: "차수"는 **시간에 따른 군집 변화**(주간/월간 스냅샷 비교)를 의미.
- **핵심 발견**: `public/data/{title}.json`은 nightly 파이프라인이 매일 git에 커밋해왔음(pepp-us 기준 47개 커밋 확인) — **git 히스토리가 이미 암묵적 스냅샷 저장소**. 이 저장소(`ChioYoon/creativedashboard`)는 공개(public) 저장소로, GitHub 커밋 API와 `raw.githubusercontent.com` 모두 인증 없이 호출 가능함을 실제 curl로 확인. → 신규 백엔드·저장소 불필요.
- `js/data-source.js`의 `DataSource.normalizeFromJson(json) → {columns, rows, _meta}`가 이미 원시 JSON→분석용 rows 변환을 담당 — 과거 JSON에도 그대로 재사용 가능.
- `step2_clustering.html`의 군집화 핵심 로직(`aggregateByMaterial`/`calcRankScores`/`buildTagClusters`/`assignMaterialsToClusters`/`mergeSmallClusters`/`enrichClusters`)은 이미 순수 함수로 분리돼 있음. 다만 `runClustering()` 자체는 전역변수(`csvData`/`sessionConfig`)·DOM 진행바·`sleep()` 페이싱에 결합돼 있어, 과거 스냅샷 재계산을 위해 **순수 계산 부분만 추출하는 리팩터**가 필요.

## 목표

두 시점(오늘 vs N주/개월 전)의 군집화 결과를 비교해, 어떤 군집이 성장/하락했는지, 어떤 소재가 새로 들어오거나 빠졌는지, 어떤 태그가 여전히/새로 잘 나가는지를 `step2_clustering.html`에서 확인할 수 있게 한다.

## 설계

### 1. 데이터 흐름 (스냅샷 소스)

```
사용자가 "1주 전" 등 프리셋 클릭
  → GET api.github.com/repos/{owner}/{repo}/commits?path=public/data/{title}.json&until={targetDateISO}
  → 응답 중 가장 최근(첫 번째) 커밋 sha 확보
  → GET raw.githubusercontent.com/{owner}/{repo}/{sha}/public/data/{title}.json
  → DataSource.normalizeFromJson(과거JSON) → {columns, rows} (오늘과 동일 변환 경로)
  → computeClusterResults(rows, 오늘과 동일한 sessionConfig) → 과거 clusterResults (§ Task로 신규 추출)
```

**핵심 불변식**: 과거 스냅샷도 **오늘과 동일한 컬럼 선택·가중치·파라미터·활성 레이어**로 재계산한다. 설정이 다르면 결과 차이가 "실제 변화" 때문인지 "설정 변경" 때문인지 구분할 수 없기 때문.

### 2. 군집 매칭 알고리즘 (Jaccard 기반)

**소재 식별**: `mat._key || mat.소재명`(코드베이스에서 기존에 쓰이는 fallback 패턴)로 두 스냅샷 간 동일 소재를 식별. 소재 리네이밍 시 매칭이 끊길 수 있음을 알려진 제약으로 문서화(크래시 아님, 그레이스풀 저하).

**`matchClustersAcrossSnapshots(nowClusters, prevClusters, threshold=0.2)`**:
1. 오늘의 각 군집 `C_now`에 대해, 과거의 모든 군집 `C_prev`와 Jaccard 유사도 계산: `J = |겹치는 소재 수| / |합집합 소재 수|`.
2. 가장 높은 J를 가진 `C_prev`에 매칭. **`J < threshold`(초기값 0.2)면 매칭 안 함 → "신규 군집"**로 분류.
3. 어떤 현재 군집에도 매칭되지 않은 과거 군집 → **"소멸 군집"**.
4. 군집 분열/병합은 별도 특수처리 없이 단순 그리디 최고매칭 결과 그대로 노출(정교한 이분매칭은 과설계로 판단, YAGNI). `threshold=0.2`는 실측 데이터 부족 상태의 초기 추정치 — 실사용 후 조정 여지를 코드 주석에 남긴다.

**매칭된 쌍마다 표시**: 대표 태그(과거→현재), 평균점수 Δ, 등급(S~D) 변화, 소재 수 Δ, overlap 비율(%).

**요약 인사이트 블록**(기존 승리공식/중단패턴과 같은 자리에 배치): 상승 군집 Top N(avgScore Δ 내림차순) · 하락 군집 Top N · 신규 군집 목록 · 소멸 군집 목록.

### 3. UI/UX + 트리거

- **위치**: 기존 승리공식/중단패턴 인사이트 블록 바로 아래, 새 섹션 "군집 트렌드 비교".
- **트리거**: 라이브 대시보드 기간 프리셋과 동일한 패턴으로 `[1주 전] [2주 전] [1개월 전]` 버튼 — **클릭 시에만 실행**(자동 실행 안 함, API 호출·재계산 비용 고려). 클릭 시 버튼 비활성화 + "과거 스냅샷 불러오는 중..." 표시.
- **실패 처리**: 선택한 시점에 해당 커밋이 없으면(타이틀이 그만큼 오래되지 않음) "선택한 시점에 데이터가 없습니다" 안내만 표시, 크래시 없음.
- **캐싱**: `sessionStorage` 키 `r_team_cluster_trend_{titleId}_{targetDateISO}`에 fetch한 과거 rows + 계산된 clusterResults 캐시 — 같은 세션에서 같은 날짜 재클릭 시 API 재호출 없이 즉시 표시. 새로고침 시 캐시 소멸(항상 "오늘 대비"이므로 자연스러운 동작).
- **결과 렌더**: 요약 인사이트(상승/하락 Top N · 신규/소멸 군집 목록)를 먼저, 그 아래 매칭된 군집 쌍을 카드로(기존 군집 카드 스타일 재사용, 과거→현재 화살표로 대표태그·점수·등급·소재수 변화 표시).

## 불변식

- 군집 멤버십/태그 클러스터링 알고리즘 자체는 무변경(기존 로직 재사용만, 신규 알고리즘 추가 없음).
- 비교 버튼을 누르지 않으면 오늘 화면·동작은 기존과 완전히 동일.
- 활성 레이어(Google Ads/MMP)·컬럼설정·가중치는 두 스냅샷에 동일하게 적용.

## 리스크 및 대응

- **R1 GitHub API 레이트리밋**(60회/시간 무인증) — sessionStorage 캐싱으로 완화, 남용 시 안내 메시지만 추가(별도 백엔드 프록시는 이번 범위 밖).
- **R2 소재 식별자 불안정**(리네이밍 시 매칭 끊김) — 문서화된 가정. 끊기면 "신규+소멸"로 표시되는 정도로 그레이스풀 저하.
- **R3 `runClustering()` 리팩터 회귀 위험** — 순수 계산 함수 추출 시 기존 라이브 클러스터링 흐름이 리팩터 전후 동일 결과를 내는지 필수 검증.
- **R4 매칭 임계값(0.2) 미검증** — 실측 데이터 부족한 상태의 추정치. 코드 주석에 조정 여지 명시.
- **R5 과거 JSON 스키마 드리프트**(예: `campaign_canonical` 필드가 없던 과거 버전) — `DataSource.normalizeFromJson()`의 기존 방어로직에 의존(신규 방어 코드 추가 안 함).

## 검증 계획

1. pepp-us로 "1주 전" 비교 → 매칭/신규/소멸 군집 수가 합리적인지, 콘솔 0.
2. 커밋이 없을 만큼 오래된 날짜 선택 시 그레이스풀 에러 메시지 확인(크래시 없음).
3. 리팩터된 `runClustering()`이 리팩터 전과 동일한 오늘자 결과를 내는지 diff 확인(회귀 없음).
4. 같은 날짜 재클릭 시 sessionStorage 캐시로 API 재호출 없음을 network 탭에서 확인.

## 영향 파일

- `step2_clustering.html`: 순수 계산 함수 추출(`computeClusterResults`) + 매칭 알고리즘(`matchClustersAcrossSnapshots`) + 히스토리 fetch(`fetchHistoricalSnapshot`) + 트렌드 UI 신규 섹션(HTML/CSS/렌더 함수). 상세 파일/함수 분해는 계획(plan) 단계에서 확정.

## 범위 밖

- 소재 리네이밍 추적(별칭 매핑과 별개 메커니즘 필요, 이번엔 미대응).
- 3개 이상 시점의 전체 타임라인 차트(이번엔 두 시점 비교만).
- GitHub API 대체용 백엔드 프록시/캐시 서버 구축.
