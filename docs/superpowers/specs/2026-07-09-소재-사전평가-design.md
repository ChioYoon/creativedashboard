# 소재 사전평가 (기능 2) — 설계 문서

**작성일:** 2026-07-09
**범위:** 신규 페이지 `pre_eval.html` + `js/gemini-api.js` 비전 확장. 정적 사이트(GitHub Pages) 클라이언트 사이드.
**한 줄:** 신규 제작 소재(이미지)를 업로드하면, 선택 타이틀의 누적 성과 패턴에 얼마나 부합하는지 정성 등급 + 근거 + 개선 가이드를 집행 전에 제시.

---

## 1. 목표

신규 소재가 그동안 분석한 인사이트·데이터에 얼마나 부합하고 성공 가능성이 얼마나 되는지를 **집행 전에** 확인. 강점/약점 태깅에 더해 종합 인사이트·예상 평가·개선 인사이트를 제공.

**핵심 원칙(하이브리드·근거화):** Gemini는 **비전 태깅 + 언어(인사이트/개선)**를 담당하고, **정성 등급은 프런트가 그 타이틀 우수 소재들의 태그-lift 매칭으로 결정론적 산출**한다. "성공 가능성"을 모델 감(感)이 아니라 실 데이터 패턴으로 근거화. 데이터가 얇으므로(타이틀당 소재 수십 개 이하) **방향성 참고**로 프레이밍하고 정밀 %는 쓰지 않는다.

## 2. 비목표 (YAGNI)

- 영상 파일 업로드·프레임 분석 → v1은 이미지(배너/대표 프레임)만. 영상은 후속.
- 정밀 성공률 % / 실측 등급(TotalScore) 산출 → 점수는 순위 기반 상대값이라 단독 소재로 불가. 예측은 시각 신호 + 태그 패턴 기반 정성 등급.
- 파이프라인/백엔드 태깅 호출 → 정적 사이트라 백엔드 없음. 클라이언트 비전으로.
- 태그 lift 사전 집계 저장 → 로드 시 클라이언트 계산(step1 `buildTagCohortSummary`와 동일 방식).
- 크로스 타이틀 비교 → 타이틀별 게임 컨텍스트가 다르므로 선택 타이틀 1개 기준.

## 3. 아키텍처 배경 (탐색 결과)

- 파이프라인 태깅(`pipeline/tagger.py`)은 이미 "성과 없는 소재"를 시각 분석만으로 태깅 — 선행 평가의 개념적 선례.
- 고정 태그 택소노미는 `pipeline/schemas.py` Enum: 강점 13(`StrengthSignal`)·약점 7(`WeaknessSignal`)·후킹 6(`HookingStrategy`)·USP 5(`CoreUSP`)·아트 5(`VisualStyle`)·예측가설 7(`PerformanceHypothesis`).
- 프런트 `js/gemini-api.js:123` `callGeminiAPI`는 **텍스트 전용**(`contents:[{parts:[{text}]}]`) — 비전 미지원. `GeminiKeyManager`(키·플랜) 존재.
- 태그→성과 상관은 클라이언트 런타임 계산: step1 `buildTagCohortSummary`(lift = 우수군 출현율 − 저효율군 출현율), step2 `renderTagImpact`(태그별 평균점수). 저장 안 됨.
- 데이터: `public/data/{title}.json` creative 레코드에 `strengths[]·weaknesses[]·hooking_strategy·USP·art_style·hypothesis[]·scores.total·유형` 등. `js/data-source.js`로 로드.
- 게임 컨텍스트: `pipeline/game_context/{title}.md`(zeus.md 등) — 마케터가 직접 관리하는 타이틀 설명.

## 4. 상세 설계

### 4.1 페이지·입력 (`pre_eval.html`)
- 상단바(모든 페이지 공통 `<nav>`)에 5번째 메뉴 "소재 사전평가" 추가.
- 입력 컨트롤:
  - **타이틀 선택** (`js/data-source.js`의 titles.json manifest에서 데이터 보유 타이틀 목록)
  - **이미지 업로드** (drag&drop + 파일선택, `accept="image/*"`, `FileReader.readAsDataURL` → base64). 미리보기 표시.
  - (선택) **소재 컨셉/의도** 자유 텍스트 (마케터가 의도한 후킹/USP 등, 프롬프트 보조)
  - **평가 실행** 버튼
- Gemini 키: `GeminiKeyManager` 재사용. 미설정 시 안내(보고서와 동일 패턴).

### 4.2 분석 파이프라인

**(1) 타이틀 패턴 산출 (프런트, 결정론적)** — 평가 실행 시 선택 타이틀 로드 후:
- 소재를 `scores.total` 내림차순 정렬, 상·하위 절반으로 winners/losers 분할(홀수 시 중앙 제외). (step1 `buildTagCohortSummary` 동일)
- `strengthLift(tag) = winners출현율 − losers출현율`. **winnerTags** = lift ≥ +0.2 인 strength 태그.
- **riskTags** = losers에서 `ceil(losers.length/3)`건 이상 출현한 weakness 태그(저효율 공통 약점).
- winners/losers 각 2개 미만이면(소재 4개 미만) 패턴 산출 스킵 → 4.4 저데이터 경로.

**(2) 비전 태깅 + 언어 (Gemini, 1콜)** — `callGeminiVision(prompt, {mimeType, dataBase64})`:
- 프롬프트 구성: (a) 역할·규칙, (b) **고정 택소노미 전체 목록**(허용 값), (c) 게임 컨텍스트(`pipeline/game_context/{title}.md` best-effort fetch, 없으면 생략), (d) 이 타이틀 winnerTags·riskTags 목록, (e) 소재 컨셉 텍스트(있으면), (f) 출력 JSON 스키마 지시.
- 반환 JSON: `{ art_style, hooking_strategy, USP, strengths:[label…], weaknesses:[label…], hypothesis:[label…], 종합인사이트: "...", 개선가이드: ["...","..."] }` (모든 태그는 택소노미 라벨 정확히).
- 파싱 실패 시 폴백(원문 표시 + 등급 산출 스킵).

**(3) 적합도·등급 산출 (프런트, 결정론적)** — Gemini가 반환한 태그로:
- `matchedWinners = 소재.strengths ∩ winnerTags`
- `missedWinners = winnerTags − 소재.strengths`
- `heldRisks = 소재.weaknesses ∩ riskTags`
- **정성 등급 규칙(v1 휴리스틱·조정 가능):**
  - **유망**: `matchedWinners ≥ 2` 그리고 `heldRisks = 0`
  - **개선필요**: `heldRisks ≥ 2` 또는 (`heldRisks ≥ 1` 그리고 `matchedWinners = 0`)
  - **보통**: 그 외
- 부정 예측가설(`낮은 관련성 위험`·`낮은 전환 위험`·`피로도 빠를 위험`)은 등급엔 미반영하되 인사이트/개선 근거로 표시.

### 4.3 출력 (1a 카드 톤 재사용)
- **예측 등급** 뱃지(유망=초록 / 보통=회색 / 개선필요=주황) + 한 줄 요약
- **근거 태그 3묶음**: ✅ 보유 우수 태그(matchedWinners) / ⚠️ 놓친 우수 태그(missedWinners) / 🚩 보유 리스크(heldRisks) — 각 태그 뱃지
- **종합 인사이트**(Gemini): 왜 이 등급인지, 시각 신호 종합
- **개선 가이드**(Gemini): 놓친 우수 요소 보완·리스크 제거 구체책 (개조식)
- **감지 태그 요약**: art_style·hooking·USP·강점·약점(참고)
- **신뢰도 안내**: "시각 신호 + {타이틀} 소재 N개 성과 패턴 기반 **방향성 참고** · 실제 성과는 집행으로 검증 필요"

### 4.4 엣지케이스
- Gemini 키 미설정 → 실행 차단 + 키 설정 안내
- 비교 소재 4개 미만(패턴 산출 불가) → 등급 생략, **감지 태그 + Gemini 인사이트만** 표시 + "비교 데이터 부족 — 태그 기반 참고" 명시
- 이미지 형식·용량 검증(예: 10MB 이하, image/*). 초과 시 안내
- 게임 컨텍스트 .md 404 → 컨텍스트 없이 진행
- JSON 파싱 실패 → 원문 표시 폴백

## 5. 파일 변경 요약
- **신규** `pre_eval.html` — 페이지 UI + 파이프라인 오케스트레이션 + 태그-lift·등급 로직 + 결과 렌더(1a 카드 스타일 이식).
- **수정** `js/gemini-api.js` — `callGeminiVision(prompt, image, opts)` 추가(`inlineData` part). 기존 `callGeminiAPI` 무변경(무회귀). → 3 HTML 캐시버스터 대상 아님(신규 페이지만 새 함수 사용, 기존 페이지 미변경) — 단 `js/gemini-api.js`가 다른 페이지서도 로드되면 캐시버스터 확인 필요(구현 시 점검).
- **수정** `index.html` 등 상단바 `<nav>` — "소재 사전평가" 링크 추가(공통 네비 위치에 맞춰).
- 파이프라인·데이터 스키마 변경 없음.
- ⚠️ **택소노미 복제**: `schemas.py` Enum 값을 `pre_eval.html`에 상수로 복제 → 출처 주석(`// SYNC: pipeline/schemas.py`) 명시. 파이프라인 택소노미 변경 시 수동 동기화 필요.

## 7. 열린 결정 (구현 중/후 확정)
- Gemini 콜 1회(태깅+언어 결합) vs 2회(태깅→언어 분리): 기본 **1회**(효율). 품질 부족 시 분리.
- 등급 임계값(lift +0.2, 리스크 카운트)은 v1 휴리스틱 — 실사용 후 조정.
- 게임 컨텍스트 .md의 정적 서빙 경로 확인(GitHub Pages가 pipeline/ 서빙 여부) — 안 되면 zeus.json에 컨텍스트 동봉 또는 페이지 내 짧은 설명.
