## 배경 조사 결과 (완료)

### A. 제우스 데이터 검증
- **수집 vs 표시 일치**: Google Ads 사전예약 전환값이 정확히 수집·표시됨. `zeus.json` `campaign_canonical` 5개 캠페인 **전부 `ua_type: NU-Pre`(사전예약)**. MMP는 `mmp_installs: null`·`mmp_daily: []`·`mmp_quality_score: null`(설치/매출 이벤트 없음).
- **MMP 레이어 = 안전**: 데이터 없을 때 `0`이 아니라 `—`(회색 대시)로 표시 — `mmpCellHtml`([step1_integrated.html:2189-2193](step1_integrated.html:2189)) 및 4지표 dash 가드. 오독 위험 없음. ✅
- **오해 소지 1건(수정 대상)**: ADS 레이어 안내 라벨([:2363-2364](step1_integrated.html:2363))이 `"전환 · CPA · IPM · ROAS (분모=설치)"` — 제우스 사전예약 캠페인의 "전환"은 **설치가 아니라 사전예약 완료**. "분모=설치" 문구가 부정확해 마케터가 설치 지표로 오독 가능. ⚠️

### B. 추이 칼럼 + 모달 차트
- **표의 "추이" 스파크라인 칼럼은 여전히 존재**(헤더 [:1639](step1_integrated.html:1639) `<th ...data-tip="일별 전환수 추이">추이 …`, 셀 [:5209](step1_integrated.html:5209) 마지막 `<td>${sparkHtml}</td>`). 모달로 "대체"된 게 아니라 병존 → 삭제 대상.
- **모달 추이 차트 = 실제 버그**: `renderModalTrend`([:6933](step1_integrated.html:6933))가 `creative.meta.kpi_daily`를 **날짜별 합산 없이 원본 행 그대로** 플롯. 제우스는 NU-Pre 캠페인 다수라 **날짜당 여러 행**(한 소재가 07-01·07-02 2일인데 행 12개) → x축에 `07-01,07-01,07-01,07-02…` 중복 날짜 표시 = "일자별로 안 보임"의 원인. 표 스파크라인(`buildDailySparklineMap` [:4934](step1_integrated.html:4934))은 날짜별 합산을 정상 수행.

### C. DS v3
- 새 `colors_and_type.css`(403줄) vs 현재(340줄) diff: **66줄 추가, 3줄 변경** — 대부분 additive.

## 설계

### 1. 제우스 — 전환 기준 라벨 동적화 (Level 1)

전환 기준을 `window.__campaignCanonical`의 `ua_type` 분포에서 파생해 ADS 레이어 라벨에 반영.

**신규 헬퍼** (`step1_integrated.html`, `switchAnalysisLayer` 근처):
```js
// 활성 데이터의 캠페인 유형(ua_type)에서 전환 기준을 파생. NU-Pre(사전예약)만이면 '사전예약',
// 그 외/혼합이면 '설치'(현행 기본). 캐노니컬 맵 없으면 '설치' 폴백.
function detectConversionBasis() {
  const cc = window.__campaignCanonical || {};
  const uaTypes = Object.values(cc).map(v => v && v.ua_type).filter(Boolean);
  if (!uaTypes.length) return '설치';
  const allPrereg = uaTypes.every(t => t === 'NU-Pre');
  return allPrereg ? '사전예약' : '설치';
}
```

**ADS 레이어 라벨 교체**([:2363-2364](step1_integrated.html:2363)):
```js
if (hint) hint.innerHTML = `<strong>Google Ads 종합점수</strong> 기준 — Google Ads 매체 · ` +
  `전환 · CPA · IPM · ROAS <span style="opacity:.7;">(분모=설치)</span> · ${periodTxt} · 현재 집합 상대순위`;
```
을 다음으로:
```js
const _basis = detectConversionBasis();
if (hint) hint.innerHTML = `<strong>Google Ads 종합점수</strong> 기준 — Google Ads 매체 · ` +
  `전환(${_basis}) · CPA · IPM · ROAS <span style="opacity:.7;">(분모=${_basis})</span> · ${periodTxt} · 현재 집합 상대순위`;
```
→ 제우스: "전환(사전예약) … (분모=사전예약)", 펩/갓앤데몬(설치형): "전환(설치) … (분모=설치)"(현행과 동일 의미).

**불변**: MMP 레이어 라벨·계산·dash 가드 무변경(이미 안전). 전환 값 계산 로직 무변경(라벨만).

### 2. 추이 칼럼 삭제 + 모달 차트 날짜 합산 수정

**2-1. 표 '추이' 칼럼 삭제 + 전용 죽은 코드 체인 제거**

grep 확인 결과 스파크라인 체인은 **전부 추이 칼럼 전용**(모달은 `_dailyMap`이 아니라 `creative.meta.kpi_daily` 사용). 칼럼 삭제 시 아래 전체가 죽은 코드가 됨 → 함께 제거:
- 헤더([:1639](step1_integrated.html:1639)): `<th class="has-tooltip" data-tip="일별 전환수 추이">추이 <span class="th-info">?</span></th>`.
- 셀([:5209](step1_integrated.html:5209)): 행 템플릿 마지막 `<td style="text-align:center;padding:6px 4px;">${sparkHtml}</td>`.
- 행 루프 내 `sparkHtml`·`dailyData` 산출([:5143-5145](step1_integrated.html:5143)): `const dailyData = dailyMap[c.key] || [];` + `const sparkHtml = …buildSparklineSvg…`.
- `dailyMap` 읽기([:5106](step1_integrated.html:5106)): `const dailyMap = window._dailyMap || {};`.
- `_dailyMap` 빌드·저장([:5325·5328](step1_integrated.html:5325)): `const dailyMap = buildDailySparklineMap(sparkRows, currentGroupBy);` … `window._dailyMap = dailyMap;`(및 그 사이 `sparkRows` 준비 코드가 이 용도 전용이면 함께 — plan에서 정확 경계 확정).
- 헬퍼 정의: `buildSparklineSvg`([:4965](step1_integrated.html:4965)), `buildDailySparklineMap`([:4934](step1_integrated.html:4934)).

**⚠️ 안전장치**: 각 삭제 전 `grep`으로 잔여 참조 0건 재확인(plan Step에 명시). 5325 부근 `sparkRows` 등 보조 변수는 다른 소비처 있으면 보존.

**2-2. 모달 추이 차트 날짜 합산 수정** (`renderModalTrend` [:6933](step1_integrated.html:6933))
`kpi_daily`(영문 키 `conversions/impressions/cost`)를 **날짜별 합산 후** 플롯. `buildDailySparklineMap`은 CSV rows(한글 키)용이라 데이터 형태가 달라 재사용 대신 인라인 합산:
```js
function renderModalTrend(creative) {
  const cv = document.getElementById('modalTrendChart');
  if (!cv || typeof Chart === 'undefined') return;
  const rawDaily = (creative.meta && creative.meta.kpi_daily) || [];
  // ★ 날짜별 합산 (NU-Pre 등 캠페인 다수 → 날짜당 여러 행이므로 date 기준 집계)
  const byDate = {};
  for (const r of rawDaily) {
    const dt = r.date; if (!dt) continue;
    if (!byDate[dt]) byDate[dt] = { impr: 0, conv: 0, cost: 0 };
    byDate[dt].impr += Number(r.impressions || 0);
    byDate[dt].conv += Number(r.conversions || 0);
    byDate[dt].cost += Number(r.cost || 0);
  }
  const dates = Object.keys(byDate).sort();
  const labels = dates.map(d => String(d).slice(5));
  const series = {
    '전환': dates.map(d => byDate[d].conv),
    '노출': dates.map(d => byDate[d].impr),
    'CPA':  dates.map(d => byDate[d].conv > 0 ? Math.round(byDate[d].cost / byDate[d].conv) : null),
  };
  const btns = document.querySelectorAll('.trend-metric-btn');
  const setActive = (m) => btns.forEach(b => { const on = b.dataset.metric === m; b.style.background = on ? '#DC2828' : '#fff'; b.style.color = on ? '#fff' : '#374151'; });
  const draw = (metric) => {
    if (window._modalTrendChart) { try { window._modalTrendChart.destroy(); } catch (_) {} }
    window._modalTrendChart = new Chart(cv.getContext('2d'), {
      type: 'line',
      data: { labels, datasets: [{ label: metric, data: series[metric], borderColor: '#DC2828', backgroundColor: 'rgba(220,40,40,.08)', tension: .25, spanGaps: true, pointRadius: 2, fill: true }] },
      options: { responsive: true, maintainAspectRatio: false, plugins: { legend: { display: false } }, scales: { y: { beginAtZero: true } } }
    });
    setActive(metric);
  };
  btns.forEach(b => b.addEventListener('click', () => draw(b.dataset.metric)));
  draw('전환');
}
```
→ x축이 고유 날짜(07-01, 07-02)만 표시, 각 날짜값은 그날 전체 캠페인 합산. **모달 트리거 조건**(`_hasDaily` = `kpi_daily.length >= 1`, [:6807](step1_integrated.html:6807))·버튼·빈상태 안내 무변경.
