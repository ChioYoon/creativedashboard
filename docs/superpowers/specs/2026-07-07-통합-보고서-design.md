# 통합 보고서 (요약 리포트 + HTML 추출 통합) 설계

**작성일:** 2026-07-07

## Goal

주간/월간 UA 보고에서 "요약 리포트"(분석형)와 "HTML 추출"(전체 소재 데이터)을 **하나의 상세 보고서**로 통합한다. 해석(KPI 델타·AI 코멘트·무버·Top)과 데이터(전 소재 상세표)를 한 문서에 담아, 두 번 추출하던 반복을 없애고 더 상세한 단일 보고서를 제공한다.

## 배경 / 현재

- **요약 리포트**(`renderSummaryReportHtml`/`buildSummaryReportData`/`exportSummaryReport`, step1_integrated.html): 헤더 + KPI 5카드(전 기간 델타 배지) + AI 코멘트(개조식) + 주목할 소재(무버) + Top 성과 소재 + 유형별 요약. 자기완결 HTML(~820px, 인쇄용).
- **HTML 추출**(`exportResultHTML(comparison)`): 브랜드 헤더 + 스탯 5카드 + 전 기간 델타 헤더 + 필터 요약(접이식) + 유형별 요약 + **전 소재 상세표(18 기본 + 6 비교 컬럼, 썸네일)**. 자기완결 HTML(~1400px).
- **공유 인프라**(이미 존재, 재사용): `computeReportComparison(creatives, curWin, prevWin, layer, weights)` → `{curWin, prevWin, hasPrev, kpiDeltas, movers, cur, prev}`; `buildReportNarrative`+`buildReportNarrativePrompt`+`buildTagCohortSummary`(Gemini 개조식 코멘트); `creativeThumbHtml(url,type,w,h)`+`youtubeThumb(url)`(썸네일); `aggregateTypeMetrics`/`typeBlended`/`creativeLayerView`(집계); `#reportDialog`+`openReportDialog(kind)`+`defaultPrevWindow`+`getReportWeights`(비교 기간 다이얼로그).
- **진입**: 결과 툴바 버튼 `요약 리포트`→`openReportDialog()`, `HTML 추출`→`openReportDialog('html')`; 다이얼로그 `생성`→`generateReport()` 디스패처(`window._reportKind`)→`generateSummaryReport()`/`generateResultHtmlReport()`.

**겹침**: KPI/스탯 카드·전 기간 델타·유형별 요약. **요약 전용**: AI 코멘트·무버·Top. **HTML추출 전용**: 전 소재 상세표·필터 요약.

## 결정 (브레인스토밍 확정)

- **진입**: 두 버튼(`요약 리포트`·`HTML 추출`) → **`보고서` 하나로 대체**(단일 통합 보고서).
- **상세표**: **핵심 컬럼 선별**(전체 18컬럼이 아니라 핵심만) + 비교 6컬럼.
- **분석 섹션**: AI 코멘트 · 주목할 소재 · Top 성과 소재 · 필터 조건 요약 **모두 포함**.
- **구현 전략**: **요약 리포트 렌더러를 통합 보고서로 확장**(Approach A) — 재사용 최대·디프 최소. HTML 추출 경로는 제거.

## Architecture

요약 리포트의 데이터 조립·렌더 함수를 통합 보고서로 확장하고, HTML 추출에만 있던 두 섹션(필터 요약·상세표)을 더한다. 비교 엔진·AI·썸네일·집계 로직은 그대로 재사용. 전부 `step1_integrated.html` 인라인 JS.

### ① 데이터 조립 `buildIntegratedReportData` (기존 `buildSummaryReportData` 확장·개명)

`buildIntegratedReportData(creatives, comparison, narrative)` → 기존 반환 객체에 두 필드 추가:
- `filterHtml`: 현재 적용 필터 요약(접이식) — `#filterSummarySlot .filter-summary`의 outerHTML을 `<details>`로 감싼 것(HTML 추출의 기존 로직 이전).
- `detailRows`: 전 소재(레이어 데이터 보유) 핵심 지표 + 비교. 각 행 = `{ thumb, name, type, 전환, 비용, CTR, CPA, ROAS, score, grade, scoreBasis, scoreCur, scorePct, convBasis, convCur, convPct }`.
  - 표시 지표는 `creativeLayerView(c)`(활성 레이어) 사용. 비교값은 `comparison.cur`/`comparison.prev`를 `key`로 매칭(있을 때만; 없으면 비교 필드 null).
- 기존 필드(`titleName, period, layer, kpis, topN, typeRows, insightHtml, comparison, narrative`)는 유지.

### ② 렌더 `renderIntegratedReportHtml` (기존 `renderSummaryReportHtml` 확장·개명)

기존 섹션(헤더·KPI 델타 카드·AI 코멘트·주목할 소재·Top·유형별 요약) 유지 + 아래 2섹션 추가:
- **필터 조건 요약**: `data.filterHtml`(있을 때만).
- **소재 상세표**: 핵심 컬럼 + 비교. 헤더/행 컬럼 = 미리보기·소재명·유형·전환·비용·CTR·CPA·ROAS·종합점수·등급 + (비교 있으면) 점수(기준/비교/변화율)·전환(기준/비교/변화율).
  - 미리보기 셀은 `creativeThumbHtml(thumb, type, 64, 42)` 재사용.
  - 변화율 배지: 점수·전환 상승=녹/하락=적, 기준 0/없음 → `—`(기존 `exportResultHTML`의 `pctBadge` 산식과 동일).
  - 비교 컬럼은 단일 `hasCmp = !!(comparison && comparison.hasPrev)` 게이트(헤더 th·행 td 동시).
- 레이아웃: 분석 섹션은 인쇄용 폭(~880px). 상세표는 자체 `overflow-x:auto` 컨테이너로 감싸 본문 가로 스크롤 없이(넓은 표만 내부 스크롤).

### ③ 진입/배선 단순화

- 결과 툴바: `요약 리포트`·`HTML 추출` 버튼 2개 제거 → `보고서` 버튼 1개(`onclick="openReportDialog()"`).
- `#reportDialog` 제목 고정("보고서 생성"), `생성` 버튼 → `generateReport()`.
- `openReportDialog(kind)` → `openReportDialog()`(kind 제거); `generateReport()`는 디스패처 없이 통합 보고서 생성만.
- `generateReport()`(개명, 기존 `generateSummaryReport`) async: 다이얼로그 값 → `computeReportComparison` → (키 있으면) `buildReportNarrative` → `exportIntegratedReport(cmp, narrative)`.
- **제거**: `exportResultHTML`, `generateResultHtmlReport`, `window._reportKind`, 리포트-종류 분기.

## Data Flow

1. `보고서` 버튼 → `openReportDialog()`(현재 기간 표시, 비교 기간 기본값 = 직전 동일 길이).
2. `생성` → `generateReport()` → `computeReportComparison(currentCreatives, curWin, prevWin, layer, getReportWeights())`.
3. 키 있으면 `showLoadingIndicator('AI 코멘트 생성 중...')` + `await buildReportNarrative(cmp, currentCreatives)`(무키/실패 → '').
4. `exportIntegratedReport(cmp, narrative)` → `buildIntegratedReportData` → `renderIntegratedReportHtml` → Blob 다운로드(`보고서_YYYYMMDD_HHMM.html`).

## Error Handling / Edge Cases

- `currentCreatives` 없음 → 기존 alert 가드(`openReportDialog`).
- 비교 기간 미입력/역전 → 기존 `defaultPrevWindow` 기본값; prev 데이터 0 → `hasCmp` false → KPI 델타 배지·상세표 비교 6컬럼 생략, 보고서 정상.
- Gemini 키 없음/타임아웃/실패 → AI 코멘트 섹션 생략(narrative ''), 나머지 정상.
- 레이어(ads/mmp)별 지표·방향성 일관(변화율 점수·전환은 높을수록 개선; CPA 등 별도 판정 없음 — 상세표는 표시 지표만).
- 상세표 행 없음(데이터 보유 소재 0) → "표시할 소재 없음" 안내.
- 썸네일: YouTube→hqdefault, 이미지→원본, 실패/무URL→아이콘(기존 `creativeThumbHtml` 폴백).

## Testing / Verification

pytest 114 유지(파이썬 무관). preview MCP(zeus 등) 컨트롤러 런타임:
1. 버튼: 툴바에 `보고서` 1개만(요약·HTML추출 버튼 없음), 클릭 → 다이얼로그(제목 "보고서 생성"), 비교 기간 기본값.
2. 생성 → 단일 HTML: 헤더·KPI 델타·(키 시)AI 코멘트·주목할 소재·Top·유형별·필터 요약·상세표 모두 존재.
3. 상세표: 핵심 컬럼 + 비교 6컬럼, 값 정합(`computeReportComparison` 대조), 썸네일(영상 YouTube), 헤더 th 수 == 행 td 수.
4. 비교 기간 없음 → 델타 배지·비교 6컬럼 생략(하위 정상), 나머지 렌더.
5. 무키 → AI 코멘트 생략, 보고서 정상 다운로드. 콘솔 에러 0.
6. `exportResultHTML`/`generateResultHtmlReport`/`_reportKind` 참조 잔존 0(제거 확인).

## 단계화 (구현 계획용)

- **Task 1** — 데이터·렌더 확장: `buildIntegratedReportData`(filterHtml·detailRows 추가)+`renderIntegratedReportHtml`(필터·상세표 섹션 추가)+`exportIntegratedReport`. 요약 함수 개명. 통합 HTML 산출.
- **Task 2** — 진입/배선 단순화 + 구 경로 제거: 툴바 버튼 1개화, `openReportDialog()`/`generateReport()` 단순화, `exportResultHTML`·`generateResultHtmlReport`·`_reportKind` 제거.

각 Task 독립 검증 가능(Task 1 = 새 렌더 산출물, Task 2 = 진입·정리).

## Out of Scope (YAGNI)

- 상세표 전체 18컬럼 유지(핵심 컬럼만 — 확정).
- 세부점수 4컬럼·IPM·매출·노출·클릭 컬럼(핵심 선별에서 제외).
- 스케줄링·이메일/Slack 자동 발송.
- .pptx 생성(HTML 인쇄→PDF 유지).
- 상세표 정렬·필터 UI(정적 표).
- 요약/HTML추출 두 형식 병행 유지(하나로 통합 — 확정).
