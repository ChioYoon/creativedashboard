# AI 인사이트 카드 구조화 렌더링 — 설계

**작성일:** 2026-06-28
**대상:** step1 소재 성과 AI 인사이트 **무료 플랜** 카드 렌더링 (`js/gemini-api.js`, `css/gemini-ui.css`)

## 목표

무료 플랜에서 Gemini가 반환하는 단일 `winning` 슬롯(위닝+저효율+권고가 한 텍스트에 통합)을 현재의 **평평한 텍스트 블록**에서 **구조화된 카드**로 개선한다. 한 카드 안에서 위닝(초록)·저효율(주황) 영역을 색·구획으로 분리하고, 소재 항목을 지표 배지가 붙은 행으로, 즉시 권고를 배지로 렌더한다.

데이터·프롬프트·파이프라인은 **변경하지 않는다.** 순수 클라이언트 렌더 레이어만 바꾼다.

## 범위

**대상 (in scope)**
- `buildScoringSlotCards(slots)`의 **무료 단일 슬롯 경로**(`isWinningOnly` — `winning` 슬롯 1개만 활성)의 구조화 렌더.
- `css/gemini-ui.css` — 신규 zone·row·chip·callout·badge 클래스(신규 클래스만 추가, 기존 `.gai-slot-card` 등은 건드리지 않음).

**비대상 (out of scope) — 현행 유지**
- **유료 5슬롯 렌더**(winning/losing/actionItems/scaleUp/stopNow): 현재 `_slotText` 평평 렌더 **그대로 유지.** 추후 동일 컴포넌트로 확장 가능하나 이번엔 미적용.
- `buildFatigueSlotCards`(피로도 카드): 현행 유지.
- 프롬프트, 데이터 스키마, 파이프라인.
- 신규 JS 테스트 프레임워크(프로젝트엔 pytest=파이프라인 전용만 → preview 기반 검증).

> 결정 배경: 무료/유료는 Gemini 토큰 한도(무료 8,192 / 유료 65,536) 대응 전략이라 분리 자체는 타당하다. 팀의 유료 키 사용 여부가 미정이므로, 확실히 쓰는 무료 경로만 먼저 구조화하고 유료 렌더는 현행 유지한다. 유료 구조화는 동일 컴포넌트 재사용으로 나중에 저비용 확장 가능.

## 무료 winning 슬롯 텍스트 포맷 (파서 입력 — 현행 프롬프트 기준)

무료는 1회 호출로 `winning` 키 하나에 아래 구조를 통합 반환한다(`\n` 줄바꿈, `**볼드**`).

```
**[위닝 소재]**
• **소재명** (IPM X.XXX / CPA X,XXX) — 성과 우수 이유 1줄
(고효율 소재 전체 나열)
**공통 패턴**: 공통 태그·요소 — 효과 이유
**[저효율 소재]**
• **소재명** (IPM X.XXX / CPA X,XXX) — 저효율 원인 1줄
(저효율 소재 전체 나열)
**위닝 대비 차이**: 부족한 태그·요소
**즉시 권고**: [확장 🟢] 소재명 / [중단 🔴] 소재명
```

## 구조 (3계층)

### (a) 파서 — `parseFreeWinning(rawText)`

순수함수. 무료 winning 텍스트를 구조화 객체로 변환한다.

**반환 형태**
```js
{
  win:  { items: [ { name, ipm?, cpa?, reason } ], callout: { label, text } | null },  // [위닝 소재] + 공통 패턴
  lose: { items: [ { name, ipm?, cpa?, reason } ], callout: { label, text } | null },  // [저효율 소재] + 위닝 대비 차이
  recos: [ { kind: '확장'|'중단', name } ],   // 즉시 권고
  _ok: boolean                                // 인식 실패 시 false → 폴백
}
```

**파싱 규칙**
1. 리터럴 `\n` → 실제 줄바꿈으로 통일(현행 `_slotText` 1단계와 동일).
2. `**[위닝 소재]**` / `**[저효율 소재]**` / `**즉시 권고**` 마커로 3구간 분할. 마커 표기 흔들림 대비: `위닝`/`저효율`/`즉시 권고` 키워드를 포함한 `**[...]**` 또는 `**...**` 헤더 줄을 경계로 인식(괄호 유무 허용).
3. **항목행** 정규식: `^[•\-▸▪◆]\s*\*\*(.+?)\*\*\s*(?:\(([^)]*)\))?\s*(?:[—:\-]\s*(.*))?$`
   - group1 → `name`, group2 → 지표원문, group3 → `reason`.
   - 지표원문 하위추출: `IPM\s*([\d.]+)` → `ipm`, `CPA\s*([\d,]+)` → `cpa`(둘 다 optional).
4. **콜아웃**(불릿 아닌 줄) 정규식: `^\*\*(.+?)\*\*\s*[:：]\s*(.*)$` → 각 구간의 `{label, text}`(위닝=공통 패턴, 저효율=위닝 대비 차이). 구간당 1개만 채택(첫 매칭).
5. **즉시 권고**: 해당 구간에서 `\[확장[^\]]*\]\s*([^/\n]+)` → `{kind:'확장', name}`, `\[중단[^\]]*\]\s*([^/\n]+)` → `{kind:'중단', name}`. (이모지 🟢/🔴 유무 허용, `/` 구분.)
6. `_ok`: `win.items`가 1건 이상이면 `true`. 아니면 `false`(→ 폴백).

### (b) 렌더러 — `buildScoringSlotCards(slots)`의 무료 분기만 변경

- `isWinningOnly`(무료 단일 슬롯)일 때: `parseFreeWinning(slots.winning)` 호출.
  - `_ok:true` → **단일 카드** 안에 **위닝 영역(초록)** + **저효율 영역(주황)** + **권고 행** 렌더.
    - 각 영역: 헤더(아이콘+제목) → 소재행들 → 콜아웃.
    - 소재행: `소재명`(강조) + 지표 칩(`IPM`/`CPA` 중 있는 것만) + `이유`(보조색).
    - 권고 행: `확장`=초록 배지, `중단`=빨강 배지.
  - `_ok:false` → 현재 동작인 `_slotText(slots.winning)` 평평 렌더로 **폴백**.
- **그 외 모든 분기(유료·다중 슬롯)**: 코드 변경 없이 현행 렌더 유지.
- 그리드 컬럼 결정·요약 바·재분석 버튼은 현행 유지.

### (c) CSS — `css/gemini-ui.css` 신규 클래스

- `.gai-zone`, `.gai-zone--win`(초록 bg/텍스트), `.gai-zone--lose`(주황)
- `.gai-item-row`, `.gai-item-name`, `.gai-item-reason`
- `.gai-chip`, `.gai-chip--ipm`, `.gai-chip--cpa`
- `.gai-callout`, `.gai-callout--win`, `.gai-callout--lose`
- `.gai-reco-row`, `.gai-badge`, `.gai-badge--expand`(초록), `.gai-badge--stop`(빨강)

색은 대시보드 기존 테마 유지: 위닝 `#10b981`, 저효율 `#f59e0b`, 중단/빨강 계열. 신규 클래스만 추가 → 유료·피로도 카드 외관은 자동으로 현행 그대로.

## 견고성 / 에러 처리

- **graceful fallback**: `parseFreeWinning`가 `_ok:false`면 무료 카드를 현재 평평 렌더로 폴백 → Gemini 포맷 드리프트(마커 누락·형식 변형)에도 안 깨짐.
- **XSS**: 현행 `_slotText`의 이스케이프(원본 `& < >` → 엔티티) 정책을 파서/렌더 출력에도 동일 적용. 소재명·이유·콜아웃·권고 텍스트 모두 escape 후 마크업.
- **잘림(`…(잘림)`)**: 현행 잘림 배지 동작 유지(구조화 렌더에서도 표시).
- **빈 값**: winning 값 없으면 카드 숨김(현행 유지).

## 검증 (preview 기반)

JS 테스트 러너가 없으므로 `preview_eval` + 합성 픽스처로 검증한다. 파서가 순수함수라 입출력 단언이 가능하다.

**파서 단위 검증** — `parseFreeWinning`에 픽스처 입력 → 구조 단언:
1. 정상 무료 winning 텍스트 → `win.items`/`lose.items` 추출, 각 IPM·CPA 파싱, 두 콜아웃, recos(확장·중단), `_ok:true`.
2. 마커 없는 자유 텍스트 → `_ok:false`.
3. 일부 누락(저효율 없음) → win만 채워지고 `_ok:true`, lose 빈 처리.
4. XSS 페이로드(`<script>`·`&`·`"`) → 텍스트에 escape 유지.

**렌더 검증** — `buildScoringSlotCards`에 합성 무료 slots 주입 후 snapshot/screenshot:
1. 정상 → 단일 카드 내 위닝(초록)/저효율(주황) 영역·IPM/CPA 칩·확장/중단 배지.
2. 깨진 텍스트 → 평평 폴백(카드 안 깨짐).
3. XSS 페이로드 → raw 미주입(이스케이프 확인).
4. 잘림 → 잘림 배지 표시.
5. 콘솔 error 0.

## 비목표 (non-goals)

- 유료 5슬롯 렌더 변경 없음(현행 `_slotText` 유지).
- 피로도 카드 변경 없음.
- 프롬프트/데이터/파이프라인 변경 없음.
- 신규 테스트 프레임워크 없음.
