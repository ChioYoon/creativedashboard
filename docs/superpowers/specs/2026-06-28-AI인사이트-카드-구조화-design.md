# AI 인사이트 카드 구조화 렌더링 — 설계

**작성일:** 2026-06-28
**대상:** step1 소재 성과 AI 인사이트 카드 렌더링 (`js/gemini-api.js`, `css/gemini-ui.css`)

## 목표

Gemini가 반환하는 소재 성과 인사이트(`buildScoringSlotCards`)를 현재의 **평평한 텍스트 블록**에서 **구조화된 카드**로 개선한다. 위닝/저효율 영역을 색·구획으로 분리하고, 소재 항목을 지표 배지가 붙은 행으로, 권고를 배지로 렌더해 가독성과 시각 위계를 높인다.

데이터·프롬프트·파이프라인은 **변경하지 않는다.** 순수 클라이언트 렌더 레이어만 바꾼다.

## 범위

**대상 (in scope)**
- `buildScoringSlotCards(slots)` — 소재 성과 5슬롯: `winning`, `losing`, `actionItems`, `scaleUp`, `stopNow` (무료 1슬롯 + 유료 5슬롯 모두).
- `css/gemini-ui.css` — 신규 zone·row·chip·callout·badge 클래스.

**비대상 (out of scope)**
- `buildFatigueSlotCards`(피로도 카드): 진단형 텍스트라 소재행 구조가 없음. **공통 시각 정돈(간격·타이포·카드 chrome) CSS만 공유 적용**, 파서/소재행/영역분리는 적용하지 않음.
- 프롬프트(`gemini-api.js`의 prompt 생성), 데이터 스키마, 파이프라인.
- 새 JS 테스트 프레임워크 도입(프로젝트엔 pytest=파이프라인 전용만 존재 → preview 기반 검증).

## 슬롯 텍스트 포맷 (파서 입력 — 현행 프롬프트 기준)

Gemini는 슬롯별로 아래 마크다운형 텍스트를 반환한다(`\n` 줄바꿈, `**볼드**`).

- **winning (유료)**
  ```
  **[위닝 소재 분석]**
  • **소재명** (점수 XX.X / IPM X.XXX / CPA X,XXX) — 성과 우수 이유 1줄
  (고효율 소재 전체 나열)
  **공통 패턴**: 공통 태그·요소 — 효과 이유
  ```
- **losing (유료)**
  ```
  **[저효율 소재 분석]**
  • **소재명** (점수 XX.X / IPM X.XXX / CPA X,XXX) — 저효율 원인 1줄
  **위닝 대비 차이점**: 부족한 태그·요소
  **개선 방향**: 수정 제안 1줄
  ```
- **actionItems (유료)**: `• **[확장 🟢]** 소재명 — 근거`, `• **[개선 🟡]** 소재명 — 방향`, `• **[중단 🔴]** 소재명 — 이유`
- **scaleUp (유료)**: `• **1순위** 소재명 — 근거`, `• **2순위** 소재명 — 근거`, `• 확장 시 예상 효과 1줄`
- **stopNow (유료)**: `• **중단** 소재명 — 문제`, `• 교체 방향 제안 1줄`
- **winning (무료, 단일 슬롯에 위닝+저효율+권고 통합)**
  ```
  **[위닝 소재]**
  • **소재명** (IPM X.XXX / CPA X,XXX) — 이유
  **공통 패턴**: ...
  **[저효율 소재]**
  • **소재명** (IPM X.XXX / CPA X,XXX) — 원인
  **위닝 대비 차이**: ...
  **즉시 권고**: [확장 🟢] 소재명 / [중단 🔴] 소재명
  ```

## 구조 (3계층)

### (a) 파서 — `parseInsightContent(slotKey, rawText)`

순수함수. 슬롯 텍스트를 구조화 객체로 변환한다.

**반환 형태**
```js
{
  sections: [          // 무료 winning 은 win/lose 2개, 그 외는 1개
    {
      kind: 'win' | 'lose' | 'generic',   // 색·아이콘 결정
      items: [ { name, score?, ipm?, cpa?, reason } ],
      callouts: [ { label, text } ],       // 공통 패턴 / 위닝 대비 차이 / 개선 방향
    }
  ],
  recos: [ { kind: '확장'|'개선'|'중단'|'순위', name, text } ],  // actionItems·즉시 권고·scaleUp·stopNow
  note: string | null,                     // "확장 시 예상 효과", "교체 방향" 등 비-항목 보조문
  _ok: boolean                             // 인식 실패 시 false → 폴백
}
```

**파싱 규칙**
1. 리터럴 `\n` → 실제 줄바꿈으로 통일(현행 `_slotText` 1단계와 동일).
2. **무료 winning**: `**[위닝 소재]**` / `**[저효율 소재]**` / `**즉시 권고**` 마커로 텍스트를 3구간 분할 → 앞 둘은 `sections`(kind win/lose), `즉시 권고`는 `recos`.
   - **유료/그 외 단일 슬롯**: 마커 분할 없이 `slotKey`로 `kind` 결정 — `winning`→`win`, `losing`→`lose`(둘 다 `sections` 1개 + callouts), `actionItems`/`scaleUp`/`stopNow`→ `sections` 비우고 `recos`+`note`만 채움.
3. **항목행** 정규식: `^[•\-▸▪◆]\s*\*\*(.+?)\*\*\s*(?:\(([^)]*)\))?\s*(?:[—:\-]\s*(.*))?$`
   - group1 → `name`, group2 → 지표원문, group3 → `reason`.
   - 지표원문에서 하위추출: `점수\s*([\d.]+)` → `score`, `IPM\s*([\d.]+)` → `ipm`, `CPA\s*([\d,]+)` → `cpa`(셋 다 optional).
4. **콜아웃** 정규식(불릿이 아닌 줄): `^\*\*(.+?)\*\*\s*[:：]\s*(.*)$` → `{label, text}`.
5. **권고행**:
   - `actionItems`/무료 즉시권고: `**[확장 🟢]**`·`[개선 🟡]`·`[중단 🔴]` 태그 → `kind`(확장/개선/중단), 뒤 `소재명 — text`.
   - `scaleUp`: `**N순위**` → `kind:'순위'`; `확장 시 예상 효과...` → `note`.
   - `stopNow`: `**중단**` → `kind:'중단'`; `교체 방향...` → `note`.
6. `_ok`: `sections`에 item·callout이 하나라도 있거나 `recos`가 있으면 `true`. 아무것도 못 뽑으면 `false`.

### (b) 렌더러 — `buildScoringSlotCards(slots)` 재작성

슬롯별로 `parseInsightContent` 호출 후:

- **무료 winning(단일 카드)**: 카드 1개 안에 **위닝 영역(초록)** + **저효율 영역(주황)** + **권고 행**. 각 영역 = 헤더(아이콘+제목) → 소재행들 → 콜아웃. (목업 확정안)
- **유료 winning/losing**: 각 슬롯 카드에 소재행 + 콜아웃(공통 패턴 / 차이점 / 개선 방향).
- **유료 actionItems/scaleUp/stopNow**: 권고 배지 행(확장=초록, 개선=주황, 중단=빨강, 순위=중립) + `note`.
- **폴백**: 해당 슬롯 `_ok:false`면 현재 `_slotText(rawText)` 평평 렌더 그대로 사용(슬롯 단위로 독립 폴백).
- 그리드 컬럼 결정·요약 바·재분석 버튼은 현행 유지.

**소재행 렌더**: `소재명`(강조) + 지표 칩(`점수`/`IPM`/`CPA` 중 있는 것만) + `이유`(보조색).

### (c) CSS — `css/gemini-ui.css` 신규 클래스

- `.gai-zone`, `.gai-zone--win`(초록 bg/텍스트), `.gai-zone--lose`(주황)
- `.gai-item-row`, `.gai-item-name`, `.gai-item-reason`
- `.gai-chip`, `.gai-chip--score`, `.gai-chip--ipm`, `.gai-chip--cpa`
- `.gai-callout`, `.gai-callout--win`, `.gai-callout--lose`
- `.gai-reco-row`, `.gai-badge`, `.gai-badge--expand`(초록), `.gai-badge--improve`(주황), `.gai-badge--stop`(빨강), `.gai-badge--rank`(중립)

색은 대시보드 기존 테마 유지: 위닝 `#10b981`, 저효율 `#f59e0b`, 중단/빨강 계열, Com2uS 레드 강조. 기존 `.gai-slot-card` 카드 chrome(테두리·여백·radius)은 정돈해 scoring·fatigue 공통 적용.

## 견고성 / 에러 처리

- **슬롯 단위 graceful fallback**: 파싱 실패 슬롯만 평평 렌더로 폴백, 나머지 슬롯은 구조화 유지 → Gemini 포맷 드리프트에 안전.
- **XSS**: 현행 `_slotText`의 이스케이프(원본 `& < >` → 엔티티) 정책을 파서/렌더 출력에도 동일 적용. 소재명·이유·콜아웃·권고 텍스트 모두 escape 후 마크업.
- **잘림(`…(잘림)`)**: 현행 잘림 배지 동작 유지(구조화 렌더에서도 표시).
- **빈 슬롯**: 값 없으면 카드 숨김(현행 동작 유지).

## 검증 (preview 기반)

JS 테스트 러너가 없으므로 `preview_eval` + 합성 픽스처로 검증한다. 파서가 순수함수라 입출력 단언이 가능하다.

**파서 단위 검증** — `parseInsightContent`에 픽스처 입력 → 구조 단언:
1. 유료 winning 텍스트 → items 2건·각 score/ipm/cpa 추출·공통패턴 callout 1건.
2. 무료 winning 텍스트 → sections 2개(win/lose)·각 items·recos(확장/중단).
3. actionItems → recos kind 확장/개선/중단 분류.
4. 깨진 텍스트(마커 없음) → `_ok:false`.
5. 잘림·XSS 페이로드 → escape 유지·잘림 플래그.

**렌더 검증** — `buildScoringSlotCards`에 합성 slots 주입 후 snapshot/screenshot:
1. 무료 winning → 단일 카드 내 위닝(초록)/저효율(주황) 영역·칩·권고 배지 렌더.
2. 유료 5슬롯 → 슬롯별 구조화 카드.
3. 깨진 슬롯 → 평평 폴백 렌더(카드 안 깨짐).
4. XSS 페이로드 → raw 미주입(이스케이프 확인).
5. 콘솔 error 0.
