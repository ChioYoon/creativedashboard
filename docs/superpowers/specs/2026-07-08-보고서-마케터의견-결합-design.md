# 보고서 마케터 의견 결합 (1a) — 설계 문서

**작성일:** 2026-07-08
**범위:** step1_integrated.html 프런트엔드 전용 (파이프라인·데이터 스키마 무관)
**선행/후속:** 본 기능(1a)은 "마케터 의견 추가" 3부작의 1단계. 팀 공유·영속·태깅 반영은 후속 1b(누적 마케터 컨텍스트)에서 정식 설계. 소재 선행 평가는 기능 2에서 별도.

---

## 1. 목표

보고서 생성 다이얼로그에서 마케터가 분석 의견을 입력하면, AI가 그 의견을 보고서 톤(개조식)으로 정리하고 이번 기간 데이터로 **검증(뒷받침/반박/확인불가)**해 보고서에 전용 섹션으로 결합한다. AI 분석과 마케터 인사이트가 **검증형으로 결합**되어, 사람의 도메인 판단을 데이터가 뒷받침·보정한다.

**핵심 원칙(검증형):** AI는 마케터 의견을 *가설*로 받아 데이터로 검증한다. 무비판적 동조 금지. "마케터 관점"과 "데이터 근거"를 구분 표기하고, 데이터로 확인 안 되면 억지로 맞추지 않고 "확인 불가"로 명시한다.

## 2. 비목표 (YAGNI)

- 팀 공유·서버 영속·미래 보고서 자동 반영 → **1b 소관** (정적 사이트라 커밋되는 데이터 필요).
- 소재 태깅/재분석에 마케터 인사이트 반영 → **1b 소관**.
- 구조화 입력(섹션별 입력칸) → 자유 텍스트 1칸으로 충분. 불필요.
- 마케터 의견 이력/버전 관리 → 범위 밖.

## 3. 아키텍처 배경 (현재 코드)

보고서는 생성 시 실제로 Gemini AI 내러티브를 새로 만든다:

- 다이얼로그: `#reportDialog` — 현재 기간 표시 + 비교(전) 기간 date 입력(`#reportPrevStart`/`#reportPrevEnd`) + 생성 버튼(`generateSummaryReport()`).
- 내러티브: `buildReportNarrative(comparison, creatives)` → `buildReportNarrativePrompt(data, tags)` → `callGeminiAPI(prompt, {maxTokens:800, temperature:0.6})`.
- 프롬프트는 "당신은 컴투스 R마케팅팀 UA 소재 분석가…" 구조, 개조식 음슴체 4섹션(`■ 핵심 변화` / `■ 우수 요소 (저효율 대비)` / `■ 성과 좋은 소재군` / `■ 부진 요인·다음 액션`). 데이터(KPI·비교 델타·movers·Top 소재·태그 lift)로만 작성.
- 키 미설정 시 `buildReportNarrative`는 `''` 반환(내러티브 없음).
- 보고서 HTML 조립: `buildSummaryReportData()` + 다운로드(`generateSummaryReport`).

## 4. 상세 설계

### 4.1 입력 (UX)

- `#reportDialog`의 비교 기간 섹션 아래에 `<textarea id="reportMarketerNote">` 추가.
  - 라벨: "마케터 의견 (선택)". placeholder: "이번 기간에 주목한 점, 소재 판단, 다음 액션 가설 등 자유롭게".
  - 높이 ~5줄, 기존 다이얼로그 스타일(회색 테두리·12~13px) 준수.
- **선택 입력**: 비우면 현재 보고서와 바이트 동일에 준하는 동작(마케터 섹션 미출력, 프롬프트 변화 없음). 무회귀.
- **타이틀별 localStorage 기억(개인 편의)**:
  - 키: `r_team_report_marketer_note_<titleId>` (titleId 새니타이즈 — 기존 `_sessKey` 패턴 참고).
  - 다이얼로그 열 때(`openReportDialog()` — 이미 비교기간 미리채움을 담당) 저장값 있으면 textarea 미리채움.
  - 생성 시 현재 textarea 값을 저장(빈 값이면 키 삭제).
  - 명시: 이 저장은 그 브라우저 한정(팀 공유 아님). 주석으로 1b 연결 표기.

### 4.2 데이터 흐름

- `generateSummaryReport()`: `const note = (document.getElementById('reportMarketerNote')?.value || '').trim();` 읽어 localStorage 저장 후 아래로 전달.
- `buildReportNarrative(comparison, creatives, note)`: note 인자 추가(기본값 `''`).
- `buildReportNarrativePrompt(data, tags, note)`: note 인자 추가(기본값 `''`).
- 보고서 데이터 조립(`buildSummaryReportData`)에 마케터 섹션 렌더에 필요한 값 전달(정리·검증 결과는 내러티브 텍스트에 포함되므로 별도 필드 최소화).

### 4.3 AI 동작 (프롬프트 — 검증형)

`buildReportNarrativePrompt`에 note가 비어있지 않을 때만 아래를 프롬프트에 **추가**(기존 4섹션 규칙은 유지):

- 추가 섹션 2개를 **기존 4섹션보다 먼저** 출력하도록 지시: `■ 마케터 관점` , `■ 마케터 관점 검증`.
- **정리 규칙**: `■ 마케터 관점` 아래에 마케터 원문을 개조식 음슴체 불릿으로 재정리(내용 보존, 과장·추가 해석 금지).
- **검증 규칙**: `■ 마케터 관점 검증` 아래에 각 항목을 이번 기간 데이터·태그로 판정 — `뒷받침` / `반박·보정` / `확인 불가` 중 하나를 명시하고 근거(지표·태그·소재명) 제시. 데이터로 확인 안 되면 "데이터로 확인 불가"로 표기(동조 금지).
- 마케터 의견 원문은 `[마케터 의견]` 블록으로 프롬프트에 그대로 전달.
- 출력 형식은 기존과 동일(마크다운 금지, `■ ` 섹션 제목 + ` - ` 불릿).

### 4.4 출력 (보고서 렌더)

- 내러티브 텍스트(마케터 2섹션 + 기존 4섹션)는 기존 내러티브 렌더 경로를 그대로 통과 → 별도 렌더 코드 최소.
- 배치: 마케터 2섹션이 내러티브 최상단(사람 관점 먼저, 그 뒤 데이터 스토리). AI가 섹션 순서를 지키도록 프롬프트로 강제.
- 시각 구분(선택): 마케터 섹션 제목에 옅은 강조(기존 `■` 스타일 재사용, 신규 CSS 최소화).

### 4.5 엣지 케이스

- **노트 없음**: 마케터 섹션 미출력, 프롬프트에 마케터 블록 미포함 → 현재 보고서와 동일.
- **API 키 미설정**: 현재도 AI 내러티브가 없음. 이 경우 마케터 노트가 있으면 **원문 그대로** 보고서에 표시(정리·검증 생략), 없으면 미출력. (정리·검증은 Gemini 필요.)
- **AI 호출 실패**: 기존과 동일하게 내러티브 `''` 폴백. 마케터 노트는 4.5 키 미설정과 동일하게 원문 표시 폴백.

## 6. 테스트·검증

프런트 JS 테스트 하네스 없음 → 정적(grep·node 불가한 인라인은 preview 콘솔) + preview 런타임:

- 노트 입력 후 보고서 생성 → 마케터 2섹션이 최상단에 정리·검증 형태로 출력.
- 노트 비움 → 현재 보고서와 동일(마케터 섹션 없음).
- localStorage 기억 → 다이얼로그 재오픈 시 미리채움, 타이틀 바꾸면 격리.
- 검증 톤 확인 → 동조가 아니라 데이터 근거/반박/확인불가가 나오는지(샘플 의견으로).
- 무회귀 → 기존 4섹션·비교·필터·상세표·다운로드 정상.

## 7. 열린 결정 (구현 중 확정 가능)

- 마케터 섹션에 원문 verbatim을 함께 남길지(투명성) vs 정리본만: 기본 **정리본만**(사용자 요청 "개조식으로 정리"). 필요 시 원문을 옅은 subnote로 병기.
- 섹션 제목 강조 CSS 정도: 최소 유지.
