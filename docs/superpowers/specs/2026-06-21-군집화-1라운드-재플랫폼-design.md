# 군집화 1라운드 — 재플랫폼 설계 (Round 1)

작성 2026-06-21 · 코드 실측 + 사용자 합의 기반. 상위 로드맵: [개발로드맵-재정리](2026-06-20-개발로드맵-재정리.md) T2(군집화) NEXT thrust ❶.

## Context
군집화 도구(`step2_column_selector.html` → `step2_clustering.html`)는 실제로 클라이언트 JS로 작동하며(IQR 노이즈 필터 · Union-Find+Jaccard 태그 군집 · Rank 점수 · TF-IDF 대표태그 · S~D 등급), "v4.0 계획"의 Phase 1/3 상당 부분이 이미 구현돼 있다. 그러나 **현 아키텍처와 단절**돼 있다:
- 데이터를 **CSV 업로드로만** 받음 (파이프라인 `public/data/{title}.json` 미연동 → 메인에서 보던 데이터를 재업로드해야 함).
- **분석 레이어(Google Ads / MMP) 개념 전무**.
- **Com2uS 디자인 시스템 미적용**(독립 CSS).

v4.0 계획서(2026-04)는 파이프라인·레이어·실적일 윈도우 도입 *전*에 작성돼 낡았다. 그대로 알고리즘만 보강하면 단절이 굳어진다. 그래서 **2단계로 분리**한다: **1라운드 = 재플랫폼(본 문서)**, 2라운드 = v4.0 알고리즘.

### 사용자 합의 결정 (2026-06-21)
1. 통합 수준 = **별도 페이지 유지 + 데이터·디자인 통합** (메인 모놀리스를 키우지 않음).
2. 레이어 처리 = **메인처럼 레이어 토글** (군집은 태그 기반 공통, 성과 오버레이만 레이어별).
3. 분량·순서 = **단계적** (1라운드 재플랫폼 → 2라운드 v4.0 알고리즘).
4. 데이터 브리지 = **공용 모듈 추출** (step1 레이어 로직을 모듈로 빼 step1·step2 공유).
5. 디자인 시스템 = **Com2uS DS v2 패키지**(첨부 `Com2uS Design System_v2.zip`의 `colors_and_type.css` + Pretendard 셀프호스팅). 적용 범위 = **공용 도입 + step2 전면**, step1/index 완전 정렬은 차기(T4).

## Goals (Round 1)
1. step2가 **파이프라인 JSON을 자동 로드**(재업로드 제거). CSV 업로드는 폴백 유지.
2. step2에 **Google Ads / MMP 레이어 토글** 추가 — 메인과 동일 모델.
3. step2를 **Com2uS 디자인 시스템**으로 일치.
4. step1·step2가 **공용 레이어 모듈**을 공유(일관성 + 모놀리스 부채 일부 해소).
5. **기존 군집 알고리즘은 동작 보존**(변경 없음).

## Non-Goals (Round 2+)
Z-score 성과 정제 · Silhouette 품질 평가(S/A/B/C) · 자동 인사이트(승리공식·중단패턴·트렌드) · 실적일 윈도우링·날짜 필터 · 가중치 슬라이더 연동.

## Architecture

### 컴포넌트
```
js/layer-metrics.js (신규, 공용)        ← step1·step2 공유
  ├─ layerLabels(), MMP_GRADE_STYLE
  ├─ creativeLayerView(c)               (활성 레이어 표시값 묶음)
  ├─ scoreMmpItems(items), mmpQualityMetrics(a)
  └─ Google Ads 점수 산출(전환/CPA/IPM/ROAS rank → 점수·등급)
        ▲                                    ▲
        │ (인라인 정의 → 모듈 참조로 교체)      │ (신규 소비)
 step1_integrated.html                 step2_column_selector.html → step2_clustering.html
                                          ├─ data-source.js + ?title= 자동 로드 (CSV 폴백)
                                          ├─ 레이어 토글 (Google Ads / MMP)
                                          └─ Com2uS DS 적용
```

### 1. 공용 레이어 모듈 `js/layer-metrics.js`
- step1_integrated.html의 레이어 지표 로직을 **바이트 동일하게 추출** → `window.LayerMetrics` 네임스페이스로 노출.
- 추출 후보(최종 경계는 구현 계획에서 확정): `layerLabels` · `creativeLayerView` · `scoreMmpItems` · `mmpQualityMetrics` · `MMP_GRADE_STYLE` · Google Ads 점수 산출 함수(`calculateCreativeScores` 계열) + 그 의존 헬퍼.
- **창 의존성 주의**: `creativeLayerView`는 런타임 계산 필드(전환·CPA·_ads·TotalScore·등급 등)에 의존하므로, 모듈은 "파이프라인 JSON 소재 → 레이어 뷰"까지 가는 **지표 산출 경로**를 포함해야 한다(뷰 매퍼만으론 부족).
- step1: 인라인 정의를 모듈 참조로 교체(동작 동일).

### 2. step2 데이터 재플랫폼
- 두 step2 페이지가 `data-source.js`의 `loadCreativeData('json-url')` + `readTitleFromUrl()`로 **파이프라인 JSON 자동 로드**.
- `?title=` 없으면/로드 실패 시 **CSV 업로드 폴백** UI 유지(독립 동작 보존).
- 로드된 소재의 raw meta(`meta.mmp_quality_score`, `meta.kpi_*`, 태그 필드)를 공용 모듈로 레이어 지표화.

### 3. 레이어 토글
- step1과 동일 UI 패턴(Google Ads / MMP 버튼). `window.currentAnalysisLayer` 동일 규약.
- **군집(태그 기반)은 1회 공통 산출** — 레이어 무관(태그 동일).
- **군집 내 성과 점수·등급·대표 지표는 선택 레이어로 전환**(공용 모듈 `creativeLayerView`/`scoreMmpItems` 사용).
- 1라운드는 **전체 기간 기준**(실적일 윈도우 미반영) — UI에 "전체 기간 기준" 라벨 명시.

### 4. Com2uS 디자인 시스템 v2 적용
- v2 패키지의 **`colors_and_type.css`를 단일 토큰 소스로 벤더링·도입**(하드코딩 hex 금지, CSS 변수만 사용). 웹 적용분: `colors_and_type.css` + `fonts/*.woff2`(PretendardVariable + Regular/Medium/SemiBold/Bold/ExtraBold/Black) + 로고 PNG. Noto Sans KR은 CSS 내 @import(CDN).
- ⚠️ v2 토큰 primary 폰트 = **Noto Sans KR**(CDN) + **Pretendard 셀프호스팅 폴백**(woff2). 패키지 산문은 "Pretendard 우선"이라 하나 **토큰 파일(colors_and_type.css)이 기준**.
- step2 두 페이지를 v2 토큰·컴포넌트 클래스(`.ds-table`·`.ds-pill`·`.ds-chip`·`.ds-label`·카드 등)로 **전면 재스타일**. 독립 `:root`(--red #E84855 등) 제거.
- **무이모지** 브랜드 원칙 준수(스마일은 로고에만) — step2 신규 UI 이모지 미사용. (기존 화면의 이모지 정리는 별건.)
- 범위: **공용 DS 도입 + step2 전면**. step1/index의 v2 완전 정렬(폰트 primary 통일 포함)은 **T4 후속** — 단기적으로 step1(Pretendard)·step2(Noto primary) 미세차 가능, 정렬 시 해소.

## 데이터 흐름 (Round 1)
```
메인(step1) 에서 "Step 2 군집화" 링크 → step2_column_selector.html?title={id}
   → data-source.js 가 public/data/{id}.json 자동 로드 (없으면 CSV 업로드 폴백)
   → 컬럼 선택/가중치 (기존 UI, DS 적용) → sessionStorage
step2_clustering.html
   → 동일 title JSON + 설정 로드
   → [레이어 토글] Google Ads / MMP
   → 군집 산출(기존 알고리즘, 태그 기반·공통)
   → 군집 성과 점수·등급·지표 = 공용 모듈로 선택 레이어 기준 산출 (전체 기간)
   → 결과 렌더(Chart.js + 매핑 테이블, DS 스타일)
```

## Risks & 대응
- **R1. step1 회귀** (모듈 추출이 바이트 동일이 아니면 메인 수치 변동). → 추출 후 **기존 불변값 재검증**: 전체 MMP 품질 재계산 == 파이프라인 49/49, ads 전체 노출수 == top-level, 라이브 유형요약 == export, 콘솔 0. 불일치 시 추출 롤백·수정.
- **R2. creativeLayerView 의존 필드 누락** (step2에서 산출 경로 불완전 → 점수 NaN/—). → 모듈이 JSON→뷰 산출 경로를 포함하도록 설계, step2에서 pepp-us로 실값 검증.
- **R3. Google Ads 점수 메인과 불일치** (step2 전체기간 vs 메인 윈도우). → 의도된 차이("전체 기간 기준" 라벨). MMP 품질은 파이프라인 사전계산값이라 일치.
- **R4. CSV 폴백 회귀** (재플랫폼 중 기존 CSV 경로 깨짐). → CSV 업로드 경로 동작 유지 검증.

## 검증 계획
- **step1 무회귀**(R1 불변값) — preview, pepp-us.
- **step2**: ① `?title=pepp-us` 자동 로드(재업로드 없이 소재 표시) ② 레이어 토글 시 군집 공통·성과 지표 전환 ③ 군집 산출 정상(기존 대비 동일 군집) ④ DS 적용(색·폰트·카드) ⑤ CSV 폴백 동작 ⑥ 콘솔 0.
