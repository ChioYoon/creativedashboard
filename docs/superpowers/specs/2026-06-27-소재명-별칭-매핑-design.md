# 소재명 별칭 매핑 + 미매칭 리포트 — 설계 문서

**작성일**: 2026-06-27
**선행**: QA #2(`resolve_concept` 일원화, 커밋 6c7c0e0) — 비표준 자동생성명(유형 a) 해결
**대상**: 명명 체계가 다른 경우(유형 b) — Google Ads/MMP 광고 자산명 ≠ GDrive 소재명 (예: gd AppsFlyer `ConnectBNR` ≠ `P-DA-Reward-gacha-01`)

## 목표

Google Ads(KPI)·MMP(AppsFlyer/Airbridge) 광고 자산명이 GDrive 파일명(소재명)과 달라 조인되지 않는 소재를, **수동 별칭 맵**으로 올바른 소재에 귀속시킨다. 또한 미매칭(집행은 있으나 미조인) 소재를 **대시보드에 노출**해 "매핑 안 됨"을 잊지 않게 한다.

## 비목표 (YAGNI)

- 퍼지(유사도) 자동 제안 — 차기 (오매칭 위험)
- client-side 즉시 재귀속(localStorage) — 단일 진실원(config) 유지
- 라이브 대시보드 패널 — step1만
- 비표준 자동생성명(유형 a) 처리 — 이미 `resolve_concept`(#2)가 해결

## 결정 사항 (브레인스토밍 합의)

- **옵션 1**: 대시보드는 "표시 + 매핑 입력 UI + config 생성"만. 저장·조인은 파이프라인이 `titles_overrides.json`을 읽어 수행(단일 진실원, 정적 사이트라 직접 저장 X).
- **범위**: Google Ads + MMP 둘 다.
- **패널 위치**: step1_integrated.html 만.

## 아키텍처 & 데이터 흐름

```
titles_overrides.json  { "{title}": { "_creative_name_aliases": { "ConnectBNR": "P-DA-Reward-gacha-01", … } } }
        │  (운영자 config — 파이프라인이 직접 읽음, 단일 진실원)
        ▼
파이프라인 (main.py)
  ├ KPI 조인(Google Ads) + MMP 조인(AppsFlyer/Airbridge):
  │    resolve_concept(자산) ∉ candidate_concepts → alias_map 조회 → 후보 소재명에 귀속, 아니면 미매칭
  └ 미매칭(집행O·미조인) 자산 → CreativeDataset.unmatched_assets
        │   {concept, source(google_ads|mmp), impressions, cost, asset_types}
        │   필터: Google Ads = impr>0 + IMAGE/YOUTUBE_VIDEO(TEXT/MEDIA_BUNDLE 제외) / MMP = installs·impr>0
        ▼
  public/data/{title}.json  (신규 top-level: unmatched_assets)
        ▼
대시보드 step1_integrated.html
  └ "⚠️ 미매칭 집행 소재 N건" 패널(결과 상단) — 자산별 노출/비용/소스 + 소재명 드롭다운(매핑 대상 선택)
       + "별칭 config 복사/다운로드" → titles_overrides.json 의 {title} 항목에 병합
        ▼
  다음 파이프라인 실행 → 별칭 적용 조인 → 미매칭 목록 축소
```

**핵심 원칙**:
- 단일 진실원 = `titles_overrides.json`(파이프라인이 직접 읽음). 대시보드는 표시·매핑입력·config생성만.
- 별칭 키 = `resolve_concept` 출력(미매칭 concept). 사이즈 변형(L/S/V)이 한 concept 공유 → 별칭 1건이 전 변형 커버.
- `resolve_concept`(순수 파싱, #2) 불변 — 별칭은 **조인 단계에서만** 조회.
- 잊음 방지: 미매칭이 매 산출마다 패널 노출.

## 컴포넌트

### C1. 별칭 로더 — `pipeline/main.py` (신규)

```python
def _load_creative_aliases(title: str, repo_root: Path) -> dict:
    """js/titles_overrides.json 에서 {title}._creative_name_aliases 직접 로드(dict).
       registry(CLOOP_REGISTRY_XLSX) 활성 여부와 무관하게 동작. 없으면 {}."""
```

`resolve_config` 양 분기(단일/배치)에서 `cfg["creative_name_aliases"] = _load_creative_aliases(cfg["title"], _REPO_ROOT)`.

⚠️ `titles_overrides.json`은 현재 `registry.py`(빌드 시 병합)만 읽는다 — registry 미활성 시 main.py가 읽는 `titles.json`엔 반영 안 됨. 따라서 별칭은 **main.py가 overrides를 직접** 읽어야 항상 동작한다.

### C2. 별칭 인식 조인 — `pipeline/main.py`

**KPI 조인** (현 `resolve_concept` 사용 지점):

```python
aliases = cfg.get("creative_name_aliases") or {}
for row in kpi_rows:
    concept = resolve_concept(row.creative_name)
    if concept not in candidate_concepts:
        concept = aliases.get(concept, concept)   # 별칭 → 후보 소재명
    if concept in candidate_concepts:
        kpi_index.setdefault(concept, []).append(row)
    else:
        # 집행O(impr>0) + IMAGE/YOUTUBE_VIDEO 면 미매칭 수집
        _collect_unmatched(row, "google_ads")
```

**MMP 조인** (`inject_mmp_into_records`) — 시그니처에 `candidate_concepts`·`aliases` 추가:

```python
def inject_mmp_into_records(records, mmp_daily, source_name="airbridge",
                            currency=None, fx_rate=None,
                            candidate_concepts=None, aliases=None):
    ...
    for d in mmp_daily:
        c = resolve_concept(d.creative_name)
        if candidate_concepts and c not in candidate_concepts:
            c = (aliases or {}).get(c, c)
        by_concept.setdefault(c, []).append(d)
    # candidate_concepts 제공 시: by_concept 키 중 후보에 없고 활동(installs/impr>0) 있는 것 → 미매칭 수집
```

기존 산식·조인 동작 불변 — 별칭 재매핑 + 미매칭 수집만 추가.

### C3. 미매칭 수집 + 스키마

`pipeline/schemas.py` — `CreativeDataset`에 추가:

```python
unmatched_assets: list = Field(default_factory=list,
    description="집행O·미조인 자산 (concept,source,impressions,cost,asset_types) — 별칭 매핑 대상")
```

`pipeline/main.py` — KPI·MMP 조인에서 concept별 집계:
- 항목: `{"concept": str, "source": "google_ads"|"mmp", "impressions": int, "cost": float, "asset_types": list[str]}`
- 필터: Google Ads = `impressions>0` + `asset_type ∈ {IMAGE, YOUTUBE_VIDEO}` (TEXT·MEDIA_BUNDLE 제외). MMP = `installs>0 or impressions>0` (MMP 행엔 asset_type 없음 — 활동분 전부; MMP 광고명은 통상 배너/영상).
- 별칭으로 매핑된 자산은 미매칭에서 제외(패널엔 "아직 매핑 안 된 것"만).
- `noise`/`organic` 등은 이미 채널 제외 단계서 걸러짐.

### C4. 대시보드 패스스루 — `js/data-source.js`

`normalizeFromJson._meta`에 추가 (campaign_canonical과 동일 패턴):

```javascript
unmatched_assets: Array.isArray(data.unmatched_assets) ? data.unmatched_assets : [],
```

### C5. 대시보드 패널·매핑 UI — `step1_integrated.html`

- 로드 시 `window.__unmatchedAssets = (normalized._meta && normalized._meta.unmatched_assets) || []` (JSON 경로). CSV 경로는 `[]`.
- **패널** `#unmatchedPanel` — 결과 영역 상단, `__unmatchedAssets.length` 일 때만 표시. 헤더 "⚠️ 미매칭 집행 소재 N건 — 매핑 필요".
- 항목별: concept · 소스 배지(Google Ads/MMP) · 노출 · 비용 · asset_types · **소재명 드롭다운**(데이터셋 `creatives`의 소재명 목록).
- **"별칭 config 복사/다운로드"**: 대상 선택된 항목으로 `"_creative_name_aliases": { "<concept>": "<선택 소재명>", … }` 스니펫 생성 + 안내("`titles_overrides.json`의 `{title}` 항목에 병합 → 다음 실행 반영").

## 에러 처리 / 하위호환

| 상황 | 동작 |
|---|---|
| `unmatched_assets` 부재(구 JSON) | 패널 숨김, 무크래시 |
| 미매칭 0건 | 패널 숨김 |
| 별칭 맵 없음 | 별칭 미적용(현행 조인 그대로) |

| 드롭다운 미선택 항목 | config 스니펫에서 제외 |
| CSV 모드 | `__unmatchedAssets=[]` → 패널 숨김 |

## 테스트

### 파이프라인 (pytest)
- `_load_creative_aliases`: overrides에 별칭 있음/없음/파일부재 → dict/{}.
- 별칭 조인(KPI): 자산 concept X(비후보) + 별칭 X→Y(후보) → Y에 귀속, 미매칭서 제외. 별칭 없으면 미매칭.
- 미매칭 수집: 집행O(impr>0)·비후보·미별칭 → unmatched_assets 포함(concept/source/impr/cost/types). TEXT·impr=0 제외.
- MMP 별칭 조인 + 미매칭 수집(`inject_mmp_into_records` candidate/aliases 인자).
- 스키마: `unmatched_assets` 기본 `[]` 직렬화.
- 회귀: `resolve_concept`·기존 조인 산식 불변, 기존 테스트 통과.

### 대시보드 (수동/preview — 정적 HTML)
- `unmatched_assets` 포함 JSON 주입 → 패널 표시·소스배지·드롭다운에 소재명 채움.
- 대상 선택 → config 스니펫 정확 생성(선택분만, 현재 타이틀 키).
- 구 JSON(필드 없음)·미매칭 0건 → 패널 숨김, 콘솔 0.
