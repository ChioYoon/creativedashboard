# CLOOP 개발 로드맵 (재정리 v1)

작성 2026-06-20 · 코드 실측 기반 전수 점검 후 재구성.
**목적**: 흩어진 완료보고서·단계계획서·메모를 대체하는 **단일 개발 로드맵 출처(single source)**. 선형 Stage 0~7 모델을 폐기하고 **병렬 트랙(T1~T4) + 횡단 품질** 모델로 재정의한다.

> 범례 — 규모: **S**(반나절~1일) · **M**(2~5일) · **L**(1주+). 가치: 高/中/低.
> 상태: ✅완료 · ⚙️작동(개선여지) · ⚠️부분 · ⛔미구현 · ⏸️보류.

## 0. 한 줄 요약
정식 스테이지(0~7) 백엔드는 **전부 완료·nightly 가동 중**이며, 정식 계획에 없던 기능(군집화·AI 인사이트·피로도·위험신호·교차 성과·백분위·신뢰도·레이어 분리)까지 실제 제품에 포함돼 있다. 남은 일은 **① 소규모 정리(NOW) ② 핵심 thrust 1개 선택(NEXT, 미정) ③ 대형/조건부 과제(LATER)** 로 정리된다.

## 1. 시스템 전체 지도 — 3 구성요소
| # | 구성요소 | 정체 | 상태 |
|---|---|---|---|
| A | 메인 대시보드 `step1_integrated.html` (6,992줄) | 소재 성과 분석 | ✅ 가동 |
| B | 군집화 도구 `step2_column_selector.html` → `step2_clustering.html` (합 4,944줄) | 소재 군집 분석. Step1 상단 링크 → `?title=`·sessionStorage 연동 | ⚙️ v3.x 작동, v4.0 보류 |
| C | Python 파이프라인 (nightly 13:00 KST) | 스캔→Gemini 태깅→Google Ads/Airbridge→`public/data/{title}.json` | ✅ 가동 |

데이터 흐름:
```
GDrive 소재 → scanner → Gemini 태깅(캐시) → ┬ Google Ads API (kpi_daily)
                                            └ Airbridge MMP (mmp_daily, 일자별·페이지네이션)
   → scoring → {title}.json → 대시보드(A)  ── "Step 2 군집화" 링크 ─→ 군집화 도구(B)
        ↳ 분석 레이어(Google Ads / MMP) 완전 분리 · 실적일 윈도우링 · 코호트 임계값
```

## 6. 운영·보안 메모
- nightly `CLOOP-Nightly` 매일 13:00 KST: 파이프라인 실행 + auto git push + 이메일. **작업트리 코드로 실행**(미커밋 코드도 반영 — 양날의 검).
- `.env`에 라이브 시크릿(GEMINI_API_KEY·SMTP_PASSWORD·AIRBRIDGE_API_TOKEN). **gitignore 유지, 절대 커밋·노출 금지.**
- Gemini 무료 quota: 일 요청수(RPD) 제약, KST 16:00 리셋. 낮 수동 재태깅 시 nightly 몫 소진 주의.
- 레이어 라벨/툴팁 변경은 `layerLabels()` 1곳에서만(2026-06-20 단일화).
