# 리포트 분석형 강화 (기간비교·무버·AI 내러티브) 설계

**작성일:** 2026-07-07

## Goal

주간/월간 UA 보고의 반복 수작업을 줄이기 위해, "요약 리포트"와 "HTML 추출"을 **단순 지표 나열 → 분석형 보고서**로 강화한다. 세 축: ① 기간 대비 변화(전주/전월 대비 증감), ② 하이라이트/무버(급등·급락·신규 소재 자동), ③ AI 내러티브(Gemini 자동 코멘트).

## 배경 / 현재

- **요약 리포트**(`buildSummaryReportData`+`renderSummaryReportHtml`, step1_integrated.html): 헤더·KPI 5카드·Top5 소재·유형 요약·인사이트의 **단일 기간 스냅샷**. 변화·해석이 없어 "나열"에 그침.
- **HTML 추출**(`exportResultHTML`): 전체 소재 상세 테이블 덤프.
- 대시보드엔 이미 **기간 비교 machinery**가 있음: 피로도 탭이 `buildFatiguePeriodScores(creatives, winStart, winEnd, layer, weights, gcamps, mcamps)`로 두 기간(기준/비교)의 소재별 점수·CPA·순위를 산출하고 `aggGadsWindow`/`aggMmpWindow`로 기간 집계함 → **재사용**.
- **AI 인사이트**: `runScoringAIInsight`(js/gemini-api.js, Gemini)가 `#scoringAIBox`에 렌더 → **확장**.

## 결정 (브레인스토밍 확정)

- 비교 기간: **리포트 생성 시 별도 지정**(직전 동일길이 기본값, 수정 가능).
- 내러티브: **AI(Gemini)** 기존 연동 확장(키 없으면 우아하게 생략).
- 범위: **요약 리포트 + HTML 추출 둘 다** 강화.

## Architecture

기존 기간 집계·점수 함수와 Gemini 연동을 재사용하는 **공유 비교 엔진** 위에, 리포트 생성 다이얼로그와 두 리포트 렌더를 얹는다. 전부 `step1_integrated.html` 인라인 JS(단, AI 프롬프트는 gemini 연동 재사용).

### ① 공유 비교 엔진 `computeReportComparison`

`computeReportComparison(creatives, curWin, prevWin, layer, weights)` → 비교 데이터 객체.
- `curWin`/`prevWin` = `{start, end}` (ISO). `curScored = buildFatiguePeriodScores(creatives, curWin.start, curWin.end, layer, weights)`, `prevScored = 동일(prevWin)`. 두 결과를 `key`로 매칭.
- **집계 델타** `kpiDeltas`: 각 지표(전환·비용·노출수·평균점수)에 대해 `{cur, prev, deltaAbs, deltaPct}`. 기간 합/평균은 scored 객체 필드 합산(전환·비용·노출수) 및 점수 평균.
- **무버** `movers`:
  - `risers`: cur∩prev 중 점수 상승 상위 N(기본 3). `fallers`: 하락 상위 N.
  - `newcomers`: prev에 없고 cur에 있는 소재(신규 집행) 상위 N.
- 레이어 인지(ads/mmp). prev 데이터 없으면(`prevScored` 빈) `kpiDeltas` = cur만(delta=null), `movers.newcomers`=cur 전체가 아닌 "이전 데이터 없음" 플래그.
- 반환: `{ curWin, prevWin, hasPrev, kpiDeltas, movers }`.

### ② 리포트 생성 다이얼로그 (공유 모달)

- "요약 리포트"·"HTML 추출" 버튼 클릭 → 신규 모달 `#reportDialog` 오픈.
- 필드: 현재 기간(읽기전용, `#startDate`/`#endDate` 반영) + **비교 기간 입력**(`#reportPrevStart`/`#reportPrevEnd`, 기본값 = 직전 동일길이: `prevEnd = curStart - 1일`, `prevStart = prevEnd - (curLen-1)`) + 리포트 종류(요약/HTML, 진입 버튼이 결정) + "생성" 버튼.
- "생성" → `computeReportComparison` 호출 → 해당 리포트 렌더(요약이면 AI 내러티브 async 포함). 완료 시 다운로드(기존 Blob 패턴) 또는 새 창.

### ③ 요약 리포트 강화

- `buildSummaryReportData(creatives, comparison)` 확장: `comparison`(엔진 결과)을 받아 반환 객체에 `kpiDeltas`·`movers` 추가.
- `renderSummaryReportHtml(data)`:
  - KPI 카드에 **델타 배지**(▲+340 / ▼-12%, 색: 개선=녹/악화=적, 지표 방향성 반영 — CPA는 하락이 개선).
  - 신규 **"주목할 소재"** 섹션: 급등(riser)·급락(faller)·신규(newcomer) 각 최대 3, 썸네일+변화.
  - 신규 **"AI 코멘트"** 섹션: `data.narrative`(⑤).

### ④ HTML 추출 강화

- `exportResultHTML()`가 `computeReportComparison` 결과를 받아:
  - 상단 **요약 헤더**: KPI 델타 카드(요약 리포트와 동일 계산).
  - 소재별 테이블에 **기준/비교/변화율** 컬럼 3개 추가(피로도와 동일 산식: `(비교-기준)/기준×100`). 기존 상세 컬럼 유지.

### ⑤ AI 내러티브

- 신규 `buildReportNarrative(data, comparison)`: `kpiDeltas`·`movers`·top소재를 요약한 **주간/월간 코멘트 프롬프트**를 구성해 기존 Gemini 클라이언트(gemini-api.js) 호출 → 산문 반환(async).
- 키 없음/실패 → 내러티브 섹션 생략 + "AI 코멘트: API 키 미설정" 안내(리포트는 정상 생성).

## Data Flow

1. 버튼 클릭 → 다이얼로그 오픈(현재 기간 채움, 비교 기간 기본값 계산).
2. 생성 → `computeReportComparison(currentCreatives, curWin, prevWin, layer, weights)`.
3. 요약: `buildSummaryReportData(currentCreatives, comparison)` → (async) `buildReportNarrative` → `renderSummaryReportHtml` → 다운로드.
   HTML: `exportResultHTML(comparison)` → 요약 헤더+비교 컬럼 렌더 → 다운로드.

## Error Handling / Edge Cases

- `currentCreatives` 없음 → 기존 alert 가드.
- 비교 기간 미입력/역전(start>end) → 검증 후 기본값 강제 또는 경고.
- prev 윈도우 데이터 0 → 델타 "—/전 기간 데이터 없음", 무버는 cur 기준만(신규 판정 생략), 리포트 정상 생성.
- AI 키 없음/타임아웃/실패 → 내러티브 생략 + 안내, 나머지 리포트 정상.
- 레이어(ads/mmp)별 지표·방향성 일관(CPA·CPI 낮을수록 개선).

## 단계화 (구현 계획용)

- **Phase 1** — 다이얼로그 + `computeReportComparison` + 요약 리포트 델타·무버(규칙 기반, AI 전). 핵심 가치 즉시 제공, 동기·무의존.
- **Phase 2** — AI 내러티브(`buildReportNarrative`, Gemini, async) 요약 리포트에 추가.
- **Phase 3** — HTML 추출 강화(요약 헤더 + 비교 컬럼).

각 Phase는 독립 검증 가능한 산출물. 계획에서 Phase별 태스크로 분해.

## Out of Scope (YAGNI)

- 팀 보고 양식(섹션/순서) 강제 매칭 — 요약 리포트 자체 구조 사용.
- 스케줄링·이메일/Slack 자동 발송.
- 다중 타이틀 통합 리포트.
- 실제 .pptx 생성(HTML 인쇄→PDF 유지).
- 비교 기간 자동 감지(주/월 자동 판별) — 기본값 제공하되 사용자 지정 우선.
- 수동 ROAS 칩 재싱크 이슈(별도 발견, 무관) — 이 작업 범위 밖.
