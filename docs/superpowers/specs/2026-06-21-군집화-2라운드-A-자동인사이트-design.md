# 군집화 2라운드-A — 자동 인사이트 고도화 + 레이어 인식 설계

작성 2026-06-21 · 1라운드(재플랫폼) 완료 위에 진행. 상위 로드맵 T2 / Round 1 spec `2026-06-21-군집화-1라운드-재플랫폼-design.md`.

## Context
1라운드로 군집화(step2)가 파이프라인 JSON 자동 로드·레이어 토글·DS v2·공용 모듈을 갖췄다. 현재 step2는 "v4.0 계획"의 Phase 1(IQR·Union-Find·Jaccard·적응형 임계값)·Rank 점수·TF-IDF 대표태그·평균기반 등급(S~D)·규칙기반 인사이트(최우수/최저 군집 기반)를 이미 구현. 2라운드는 누락분을 더하는 작업이며, **사용자 결정으로 범위 A(자동 인사이트 고도화 + 레이어 인식)** 만 진행한다(B 품질 신뢰도·C 성과 정제·트렌드는 차기).

## Goals
1. **승리공식 · 중단패턴 (lift 기반)** — 활성 레이어 점수로 소재를 상위 25% vs 하위 25%로 나눠, 태그별 **lift =(상위 보유율)−(하위 보유율)** 로 성과와 상관된 태그를 도출. 승리공식=lift 상위, 중단패턴=lift 하위. 기존 군집 인사이트는 유지하고 그 위에 전용 블록 추가.
2. **레이어 인식** — `setClusterLayer` 토글 시 인사이트(`renderInsights`)·태그 히트맵(`renderTagImpact`)·신규 승리공식 블록도 **활성 레이어 점수로 재계산**(현재는 ads 기준 고정 — 1라운드 잔여).

## Non-Goals (차기)
Silhouette 품질 신뢰도(B) · Z-score 성과 정제(C) · 이전 차수 대비 트렌드 · 군집 멤버십 변경.

## Architecture / Design

### 신규 — `buildPatternInsights(clusters)` (소재 단위 lift)
- 입력: `clusters`(각 material 에 활성 레이어 `score` 이미 반영됨 — 1라운드 `applyLayerToMaterials`). material 의 군집 태그 = `m.tags`(또는 `m.topTags`).
- 절차:
  1. 전 군집의 material 평탄화 → `score` 내림차순 정렬. (점수 동률·0 포함)
  2. `k = Math.max(2, Math.ceil(n*0.25))`. 상위 k = winners, 하위 k = losers (n<4 면 인사이트 생략).
  3. 태그 집합 = winners∪losers 의 모든 `m.tags`. 각 태그 t:
     - `topRatio = (winners 중 t 보유 수)/winners.length`, `botRatio = (losers 중 t 보유 수)/losers.length`, `lift = topRatio − botRatio`.
     - 최소 지지: t 가 winners 또는 losers 에서 **2건 이상** 등장해야 후보.
  4. **승리공식** = `lift > 0` 태그를 lift 내림차순 Top 5(동률 시 topRatio). **중단패턴** = `lift < 0` 태그를 lift 오름차순 Top 5(동률 시 botRatio).
  5. 반환 `{ winners:[{tag, lift, topPct, botPct, topN}], losers:[…], n, k }`(없으면 빈 배열).
- ⚠️ 소재 단위(군집 단위 아님) — 군집이 3개뿐이어도 표본(n=소재 수) 견고. 계획서의 '군집 25%' 대안은 표본 빈약으로 미채택.

### 렌더 — 승리공식/중단패턴 블록
- `renderInsights(clusters, data)` 안에서 `buildPatternInsights(clusters)` 호출 → 결과를 인사이트 영역 **상단 전용 블록**으로 렌더(예: 두 칼럼: 🏆 승리공식 / ⛔ 중단패턴, 각 항목 `태그 · 상위 X% vs 하위 Y% · lift +Z%p`). 기존 군집 인사이트(집중투자·시너지 등) 블록은 아래 유지.
- 무이모지 원칙은 step2 기존 관행(🏆 등 기존 사용) 범위 내에서 유지 — 신규 텍스트는 가급적 아이콘(fa) 우선.

### 레이어 인식 — `setClusterLayer`
- 1라운드 `setClusterLayer`는 `applyLayerToMaterials` + `renderKPIStrip`·`renderClusterCards`·`renderCharts`·`renderMappingTable`만 재호출. → **`renderTagImpact(clusterResults)`·`renderInsights(clusterResults.clusters, clusterResults)` 추가**(활성 레이어 material score 반영).
- `renderTagImpact`/`renderInsights`가 `data`(=clusterResults: clusters·weightMap 등)를 받으므로 `clusterResults` 전체를 전달. 둘 다 material `score`(레이어 반영)·cluster `avgScore`(applyLayerToMaterials가 갱신)를 읽어 자동으로 레이어별 산출.

## 데이터 흐름
```
runClustering → renderResults: applyLayerToMaterials(ads) → renderInsights(+buildPatternInsights) · renderTagImpact (ads 기준)
레이어 토글 setClusterLayer(layer): applyLayerToMaterials(layer) → [기존 4 렌더] + renderTagImpact + renderInsights → 인사이트·히트맵·승리공식 전부 layer 기준 갱신
```

## Risks & 대응
- **R1 표본 부족**: n<4 면 승리공식/중단패턴 생략(기존 군집 인사이트만). 빈 결과 graceful.
- **R2 동률·0점 소재**: 정렬 안정성·동률 처리(lift 동률 시 ratio 보조키). winners/losers 겹침 방지(상·하위 분리, n 작을 때 k 상한 = floor(n/2)).
- **R3 레이어 토글 성능**: renderInsights/renderTagImpact 재호출은 가벼움(소재 수십 개). 문제 없음.
- **R4 군집 불변**: 본 작업은 점수·인사이트 표시만. 군집 멤버십·태그 군집화 로직 **불변**.
