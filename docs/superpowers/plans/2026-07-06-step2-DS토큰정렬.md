# step2 DS 토큰 정렬 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** step2_clustering·step2_column_selector 로컬 `:root`의 `--radius-*`·`--shadow-*` 오버라이드를 삭제해 DS 토큰(colors_and_type.css) 값을 채택하고 토큰-이름 shadowing을 없앤다.

**Architecture:** 두 페이지 모두 `colors_and_type.css`를 로드하므로, 로컬 `:root`에서 DS와 이름이 겹치는 radius/shadow 6개 선언만 삭제하면 페이지 내 `var(--radius-*)`·`var(--shadow-*)` 참조가 DS 값으로 해석된다. 구조·JS·다른 토큰은 불변.

**Tech Stack:** 정적 HTML/CSS (인라인 `<style>` 내 `:root`). 빌드 없음. 검증 = preview MCP(computed style).

**Spec:** docs/superpowers/specs/2026-07-06-step2-DS토큰정렬-design.md

## Global Constraints

- 삭제 대상 = 각 페이지 로컬 `:root`의 `--radius-sm/md/lg` + `--shadow-sm/md/lg` **6개 선언만.**
- **보존**: 브랜드/그레이 리맵(`--red`·`--gray-bg`·`--dark` 등), 클러스터 시맨틱 색(`--green`·`--orange`·`--blue`·`--purple`·`--gold` + pale/mid), `--transition`.
- 두 페이지 모두 `colors_and_type.css` 로드함 확인됨 → 삭제 후 DS 값(radius 4/8/16px, DS 그림자) 적용.
- 레이아웃·클러스터 색·브랜드 색·JS 변경 없음.
- 단일 파일 HTML 인라인 CSS 편집. 프로젝트 컨벤션 = main 브랜치 SDD.
- 검증: preview MCP로 두 페이지 `:root` computed `--radius-sm`=4px·`--radius-md`=8px, `--shadow-md`=DS 값 확인. JS 단위 테스트 프레임워크 없음.
