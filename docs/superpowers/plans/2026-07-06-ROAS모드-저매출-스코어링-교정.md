# ROAS 모드 저매출·비변별 스코어링 교정 (B+C) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** ROAS가 무의미할 때(사전예약이거나 전원 동점=비변별) 총점을 부풀리지 않도록, `calculateCreativeScores`에서 `effectiveRoasMode='off'`로 보내 기존 재배분 로직을 태운다. off 안내 메시지도 사유별로 정정한다.

**Architecture:** B(사전예약)와 C(비변별) 모두 `effectiveRoasMode='off'`로 수렴시켜 기존 off 재배분(roasWeight→나머지 3지표)을 재사용. 신규 스코어링 경로 없음. `window._roasMeta.offReason`으로 사유를 기록해 메시지를 분기.

**Tech Stack:** 정적 HTML/바닐라 JS 단일 파일(`step1_integrated.html`). 검증 = preview MCP(브라우저 eval) + pytest 무회귀.

**Spec:** docs/superpowers/specs/2026-07-06-ROAS모드-저매출-스코어링-교정-design.md

## Global Constraints

- B/C 모두 `effectiveRoasMode='off'`로 수렴 → 기존 재배분(4767-4778) 재사용, 신규 경로 금지.
- B: `roasMode==='auto'` 이고 `detectConversionBasis()==='사전예약'` → off, `offReason='prereg'`. **auto 모드에만 적용**(수동 존중).
- C: ROAS 랭크 모집단(exclude면 매출>0, 아니면 전체)이 전원 동점이면 off, `offReason='nondiscriminating'`. **수동 포함**.
- 비변별 판정 = 정렬 후 인접 차이가 모두 `< 0.0001`(기존 tie 임계와 동일).
- 재배분 조건 `roasWeight > 0` 유지. 매출 실제 변별 타이틀은 무변화(회귀 없음).
- off 안내 메시지: `offReason` = `prereg`/`nondiscriminating`/`norevenue` 별로 문구 분기.
- 단일 파일 `step1_integrated.html`. 프로젝트 컨벤션 = main 브랜치 SDD. pytest 114 passed 유지(pytest.ini로 tests/ 한정).
