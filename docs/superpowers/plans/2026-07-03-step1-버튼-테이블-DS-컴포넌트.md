# step1 버튼·테이블 공식 DS 컴포넌트 교체 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `step1_integrated.html`의 로컬 버튼(`.ds-btn-*`)·테이블(`.ds-table`) CSS를 삭제하고, 이미 로드 중인 공식 DS 파일(`assets/ds/colors_and_type.css`)의 캡슐형 필 버튼(`.ds-pill--primary/--ghost`)과 공식 테이블 스타일로 교체한다(사용자가 브라우저 목업 비교로 확정한 의도적 시각 변경).

**Architecture:** step1은 공식 DS 파일을 이미 `<link>`로 로드 중이므로, (1) 버튼은 로컬 CSS 정의 삭제 + 사용처 4곳의 클래스명 교체, (2) 테이블은 로컬 `.ds-table` 블록 삭제만으로 공식 동명 클래스가 자동 적용(HTML 클래스명 변경 불필요, 이름 충돌 해소). 1위 행 표시는 공식 `is-active`로, 종합점수 셀은 공식 `ds-cell-key`로 전환.

**Tech Stack:** 순수 HTML/CSS/JS 편집(빌드 스텝 없는 정적 사이트). 자동화 테스트 없음 — 검증은 `mcp__Claude_Preview__*` 도구로 브라우저에서 직접(렌더링·상호작용·콘솔). `pytest`는 Python 파이프라인 무회귀 세이프티넷.

## Global Constraints

- **의도적 시각 변경임**: 버튼은 각진 사각 → 캡슐형(radius 9999px, height 40px), 테이블은 패딩 7px→12~14px·본문 13px→15px — 사용자가 목업으로 보고 선택. "변화 없음"을 검증하는 것이 아니라 "공식 DS 스타일로 바뀌었는지"를 검증한다.
- 탭(`.ds-tab*`)·사이드바(`.ds-sidebar*`)·통계칩(`.ds-stat-chip*`)·앱셸은 **무변경**(공식 DS에 대응 컴포넌트 없음 — 범위 밖).
- 모든 계산 로직·데이터·정렬·필터 **동작 무변경**(CSS/클래스명만).
- `assets/ds/colors_and_type.css` **내용 무변경**.
- 인라인 스타일 처리 원칙(버튼): 공식 `.ds-pill`의 높이/패딩 모델과 충돌하는 오버라이드(`padding:*`, `font-size:*`)는 제거, 레이아웃 성격(`width:100%`, `margin-top:*`)은 유지.
- 각 태스크 완료 시 preview로 렌더링+상호작용 확인, 콘솔 error 0.
- 참고 — 공식 DS 컴포넌트 정의 위치: `.ds-pill*`는 `assets/ds/colors_and_type.css:202-216`, `.ds-table*`(+`.num`/`.ds-cell-key`/`.is-active`)는 같은 파일 281-314줄.
