# 통합 보고서 (요약 리포트 + HTML 추출 통합) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** "요약 리포트"와 "HTML 추출"을 하나의 상세 보고서로 통합 — 해석 섹션(KPI 델타·AI 코멘트·무버·Top·유형별)에 필터 요약과 전 소재 상세표(핵심 컬럼 + 비교)를 더하고, 진입 버튼을 하나로 합친다.

**Architecture:** 요약 리포트의 데이터 조립(`buildSummaryReportData`)·렌더(`renderSummaryReportHtml`)·다운로드(`exportSummaryReport`)를 **추가 확장**해 통합 보고서를 산출하고(Task 1), 진입을 단일 버튼으로 정리하며 HTML 추출 경로를 제거한다(Task 2). 비교 엔진(`computeReportComparison`)·AI(`buildReportNarrative`)·썸네일(`creativeThumbHtml`)·집계(`creativeLayerView`)는 그대로 재사용. 전부 `step1_integrated.html` 인라인 JS.

**Tech Stack:** Vanilla JS(인라인), 자기완결 HTML Blob 다운로드. 신규 의존성 없음.

## Global Constraints

- 대상 파일은 `step1_integrated.html` 단일 파일만.
- 브랜치: `main` 직접(프로젝트 컨벤션 = SDD on main).
- 진입: 결과 툴바 `요약 리포트`·`HTML 추출` 두 버튼 → **`보고서` 하나**로 대체.
- 상세표: **핵심 컬럼**(미리보기·소재명·유형·전환·비용·CTR·CPA·ROAS·종합점수·등급) **+ 비교 6컬럼**(점수 기준/비교/변화율, 전환 기준/비교/변화율). 비교 6컬럼은 `hasCmp = !!(comparison && comparison.hasPrev)` 단일 게이트(헤더 th·행 td 동시).
- 변화율 = `(비교−기준)/기준×100`, 기준 0/없음 → `—`. 점수·전환 상승=녹/하락=적.
- 상세표는 **레이어 데이터 보유 소재만**(`v.hasData`) — 나머지 리포트 섹션과 일관.
- AI 코멘트·무버는 기존 동작 유지(무키/무비교 시 graceful 생략).
- **함수명 유지**(계획상 결정): `build/render/exportSummaryReport` 이름은 그대로 두고 내용만 확장한다. spec의 "개명(Integrated)"은 이 7500줄 단일 파일에서 6개 호출부 교차수정 위험 대비 실익이 낮아 생략 — 대신 **사용자 노출 텍스트**(보고서 제목 "성과 보고서", 파일명 "보고서_", 다이얼로그 "보고서 생성", 버튼 "보고서")와 주석으로 통합본임을 명확히 한다.
- 시크릿(.env·google_ads.yaml) 읽기/출력/커밋 금지.
- 검증: pytest 114 유지(파이썬 무관). 런타임은 컨트롤러 preview MCP(구현 subagent는 편집+정적grep+pytest+커밋, preview 생략).
- 커밋: 각 Task 완료 시 `main` 커밋. push는 사용자 명시 승인 후 별도(컨트롤러).
