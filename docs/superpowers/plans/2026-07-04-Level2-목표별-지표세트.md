# Level 2 — 캠페인 목표별 지표 세트(컬럼 dim) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 캠페인 목표(사전예약/일반)에 따라 결과표의 매출·ROAS 컬럼을 흐리게(dim) 처리하고, ua_type 자동감지 + 수동 셀렉터로 목표를 제어한다.

**Architecture:** 기존 결과표의 CSS 상태클래스 컬럼 토글 패턴(`#resultTable:not(.show-mmp) .col-mmp`)을 확장. 컬럼에 시맨틱 클래스(`col-roas`/`col-revenue`)를 부여하고, `#resultTable`에 `obj-prereg` 클래스를 토글하면 CSS가 dim. 목표 판정은 기존 `detectConversionBasis()`를 단일 소스로 재사용. `renderResultTableRows`·정렬·점수 로직은 불변(셀에 클래스만 추가).

**Tech Stack:** 정적 HTML/CSS/바닐라 JS (`step1_integrated.html` 단일 파일). 빌드 없음. 검증 = preview MCP(브라우저) + pytest 무회귀.

**Spec:** docs/superpowers/specs/2026-07-04-Level2-목표별-지표세트-design.md

## Global Constraints

- 목표 2종: `사전예약`, `일반`. dim 발생은 `사전예약`만.
- dim 대상 컬럼 = **매출, ROAS 2개만.** 그 외 컬럼(비용·노출·클릭·CTR·총점·등급·성과·MMP점수)은 불변.
- dim = `opacity: 0.4` (숨김/hide 아님).
- 목표 판정 단일 소스 = 기존 `detectConversionBasis()` 재사용 (신규 ua_type 파싱 금지).
- `전환(사전예약)`/`전환(설치)` **라벨은 변경하지 않는다** — 목표는 컬럼 dim만 제어.
- 정렬·점수·헤더 라벨(`setLayerHeaders`) 로직 불변.
- 기존 파일 컨벤션 유지: `step1_integrated.html` 단일 파일 내 인라인 JS/CSS, 함수는 파일 내 기존 위치 인접에 추가.
- 프로젝트 컨벤션 = main 브랜치에서 SDD 직접 진행(피처 브랜치 없음).
- JS 단위 테스트 프레임워크 없음 → 각 태스크 검증은 preview MCP로 실제 페이지(`?title=zeus`) 로드 후 `preview_eval`/`preview_inspect` 어서션. preview MCP 불가 시 정적 grep + 함수 정의 확인으로 보상.
