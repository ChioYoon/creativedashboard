# KPI 없는 소재 모달 인사이트 게이트 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 미집행(성과 데이터 없음) 소재의 상세 모달에서 인사이트·가설·차주 변주를 숨기고 "집행 후 추가" 안내를 보이되, 강점·약점·제작 의도는 유지한다.

**Architecture:** 신규 `hasPerfData(creative)` 헬퍼로 성과 데이터 유무 판정. `buildSignalChipsHtml`는 미집행 시 가설·차주변주 그룹을 빼고, `buildInsightBlocksHtml`는 미집행 시 인사이트 대신 안내 문구를 반환. 전부 `step1_integrated.html` 인라인.

**Tech Stack:** 바닐라 JS(브라우저 인라인). `step1_integrated.html`. JS 테스트 러너 없음 → preview 서버 + `preview_eval`(캐시 우회 `?_=<ts>`).

## Global Constraints

- **점수·등급 무변경** — 이미 게이트됨(테이블 5145·5150-5151, 모달 6723-6725).
- **강점·약점·제작 의도·기본 태그·데이터·캐싱 무변경** — 가설·변주는 데이터에 그대로, UI에서만 숨김(집행 후 자동 노출).

### Task 1: hasPerfData 게이트 + 모달 2함수 적용

**Files:**
- Modify: `step1_integrated.html` — 신규 `hasPerfData`(약 2161행, `buildSignalChipsHtml` 앞), `buildSignalChipsHtml`(2162~2184), `buildInsightBlocksHtml`(2190~2199).

**Interfaces:**
- Consumes: `creative.meta`(strengths/weaknesses/hypothesis/test_ideas/one_line_insight 등), `creative._ads`, `escapeHtml` — 기존.
- Produces: `hasPerfData(creative: object) -> boolean`.

- [ ] **Step 1: `hasPerfData` 헬퍼 추가**

`buildSignalChipsHtml` 정의(약 2162행) 바로 앞에 추가:

```js
// 성과 데이터(Google Ads 노출 또는 MMP) 보유 여부 — 미집행 소재 인사이트 게이트
function hasPerfData(creative) {
  const c = creative || {};
  const m = c.meta || {};
  return !!(c._ads && c._ads.imp > 0) || !!(m.mmp_quality_score && m.mmp_quality_score.total != null);
}
```

- [ ] **Step 2: `buildSignalChipsHtml` — 미집행 시 가설·차주변주 제외**

`groups` 배열 정의(현재 2164~2169행)를 아래로 교체. 강점·약점은 항상, 가설·차주변주는 `hasPerfData` 일 때만 포함:

```js
  const meta = (creative && creative.meta) || {};
  const perf = hasPerfData(creative);
  const groups = [
    { label: '강점',      items: meta.strengths,  cls: 'signal-chip-strength',   evCls: 'evidence-strength', evidences: meta.strength_evidence },
    { label: '약점',      items: meta.weaknesses, cls: 'signal-chip-weakness',   evCls: 'evidence-weakness', evidences: meta.weakness_evidence },
    ...(perf ? [
      { label: '가설',      items: meta.hypothesis, cls: 'signal-chip-hypothesis', evCls: null,                evidences: null },
      { label: '차주 변주', items: meta.test_ideas, cls: 'signal-chip-testidea',   evCls: 'evidence-testidea', evidences: meta.improvement_actions, evPrefix: '→ ' },
    ] : []),
  ];
```

(이하 `cardCls`·`.filter`·`.map` 렌더 로직은 현행 그대로 유지.)

- [ ] **Step 3: `buildInsightBlocksHtml` — 미집행 시 인사이트 숨김 + 안내**

함수 본문 시작 `const meta = ...` 다음에 미집행 early-return 추가:

```js
function buildInsightBlocksHtml(creative) {
  const meta = (creative && creative.meta) || {};
  if (!hasPerfData(creative)) {
    return `<div class="signal-insight" style="opacity:.85;">` +
           `<span class="signal-insight-key" style="background:#9ca3af;">안내</span>` +
           `<div class="signal-insight-lead" style="font-weight:400;color:var(--text-secondary,#666);">캠페인 집행 후 성과 인사이트(가설·차주 변주)가 추가됩니다. 현재는 시각 분석(강점·약점·제작 의도)만 제공됩니다.</div></div>`;
  }
  const insight = ((meta.one_line_insight || meta.marketer_insight) || '').trim();
  const reality = (meta.kpi_reality_check || '').trim();
  if (!insight && !reality) return '';
  const lead = insight ? `<div class="signal-insight-lead">${escapeHtml(insight)}</div>` : '';
  const body = reality ? `<div class="signal-insight-body">${escapeHtml(reality)}</div>` : '';
  return `<div class="signal-insight"><span class="signal-insight-key">인사이트</span>${lead}${body}</div>`;
}
```

(`signal-insight-key` 인라인 회색 배경은 기존 키 배지 스타일을 muted 로 덮어쓰는 용도 — 별도 CSS 클래스 불필요.)
